# 执行、状态与程序核对

与共同规范一起在首次执行完整读取；本文件只规定可恢复工作记录和机械检查协议，不另建导演流程或交付主稿。用户独立格式优先，不能为校验器篡改其格式；格式不兼容时人工完成对应核对并明确程序未覆盖。

## 1. 一次取源与最小记录

有文件能力时在输出作品目录 `.storyboard/` 保存：

- `source.txt`：当前授权工作稿的UTF-8文本快照。保留原字原标点和换行，不覆盖输入；DOCX/PDF提取后先核对关键台词与阅读顺序。摘要不是完整工作稿。新授权版本另存快照，确认引用后再切换，不能静默用旧稿。
- `dialogue.json`：下面的来源索引与机械检查配置。台词在此按工作稿建立一次，不从生成的分镜反推台词表；它是来源核对载体，主稿仍只在声音栏出现完整话语。
- `state.md`：只存尚未在来源索引或主稿表达、且恢复工作确需的导演决定及简短依据、未知项、当前有效的跨场状态与未完成接点、完成位置。项目设置、版本和检查结果引用对应文件与位置；不复制台词全文、已完成镜头描述或检查报告。未变化项不重写，已闭合且不影响后续的局部项移除。
- `checks.json`：最近一次实际运行的机械检查报告，失败定位保留到修复。命令行报告自动保存本次读取的主稿、来源和索引原始字节SHA256（`input_sha256.markdown/source/ledger`）；只对这些版本有效，状态引用报告，不再手抄哈希。任一输入改变须重跑，旧报告或无指纹报告不能证明当前版本通过。

**一项内容一个存放位置：** `source.txt`保存完整授权工作稿；`dialogue.json`保存原文话语、来源区间、哈希和机械检查配置；主稿保存可执行的表演、摄影、声音及必要起落状态；`state.md`保存主稿尚未表达而恢复确需的决定与有效续接事实；`checks.json`保存机械结果。其他记录只引用场景、G单元、镜号或文件位置，不复制整段。同一决定已落实在主稿时，状态只留定位及尚需接续的差量。

**可选映射：** 不默认建立或手工维护 `mapping.json`。确有局部修改追踪或下游使用需要时，单元、镜号、时长等从当前成稿提取；末态引用正文对应单元的“落幅状态”，不复制叙述。映射是可重建的派生数据，不是另一份事实来源；生成时标明所依赖主稿的原始字节SHA256，主稿变化后按需重建，不能沿用过期映射或反向覆盖正文。

创作复审只记“具体问题 → 位置 → 修复 → 复验结果”；每场写入时保留一次已完成复审的场景/G单元范围，无问题不逐镜记通过理由，整集跨场复核完成后另留一次标记。不另建重复的长篇分析稿、状态清单和复审总结。用户要求人物/冲突分析时保留有用的简明分析，其余记录引用该结论，不重新抄写。这不省略逐场复审、整集跨场复核、后半段质量检查或主稿中独立生成所需的起落状态。

上述记录不含推理过程、候选推演或逐人逐秒清单。小任务只需够恢复的简短记录；已有记录读取后增量更新，不重新问整套问题。无文件能力在上下文保留同样的最小事实与续接位置，交付时附短摘要，不宣称跨会话自动恢复。

**生成素材交接与场景范围：** 工作记录只记需要交接的参考素材是否仅供分析、是否实际交给生成端及已确认标识；未知状态不写成已上传。每场结束核对摄影/光色基线归属当前场景，跨场不继承房间灯具或关系轴；同场停电等事件按当前实际状态续接。正文的光色转译写可见结果，记录不复制这些整段提示词。

## 2. 来源索引格式

`dialogue.json` 示例（正式文件应填真实内容，示例值不是默认台词）：

```json
{
  "version": 1,
  "source_sha256": "当前source.txt原始字节的SHA256",
  "music": true,
  "unit_music": {"G2": false},
  "max_unit_seconds": 35,
  "utterances": [
    {"id": "U001", "speaker": "林岚", "kind": "对白", "text": "不来了。", "source_start": 120, "source_end": 124}
  ]
}
```

- `source_start/source_end` 是Python Unicode字符串的字符索引，左闭右开，必须精确截取 `text`。哈希用原始字节，字符索引用UTF-8解码后的原始换行文本；不要用自动换行转换后的文本生成偏移。用脚本定位后回读相邻上下文确认同名同句的实际发生，不猜偏移。
- `utterances` 依源稿发生顺序建立，原作重复发言使用不同ID及不同来源区间。说话者用全名，`kind` 使用 `对白`、`OS`、`OV` 或 `旁白`；连续画外对白仍属对白，口型状态写演绎说明。
- 从源稿人工核对台词提取覆盖、归属、OS/OV与顺序，歧义不擅定。脚本能核对索引文字和生成稿，却不能证明模型未漏提源稿某次发言或正确理解说话者。该检查责任必须单独履行。
- 改编获授权且台词改变时，以授权后的明确工作稿建立索引，原稿另留来源；不能因校验失败擅自改源快照或索引迎合生成稿。
- `music` 为项目布尔值；`unit_music` 记录用户范围在最终单元上的布尔覆盖。新项目默认true，同项目承接已保存设置。一个单元跨开/关边界时，优先在对应镜头/时间边界拆成单元而不增加成片剪切；不便拆分时人工核对局部边界，注明该项程序未覆盖，不假称脚本已验证混合单元。

### 来源索引辅助脚本

从源稿一次提取并人工核对 `utterances.json`（JSON列表，每项含id/speaker/kind/text）后，用自带脚本自动定位字符区间和哈希，避免每次重写定位代码：

```bash
python3 <本技能目录>/scripts/index_dialogue.py <source.txt> <utterances.json> <dialogue.json> --music on --max-unit-seconds 35
```

将music和上限替换成当前项目实际设置，已关闭的续接项目必须传 `--music off`。脚本打印来源行与相邻上下文，须回读确认；它不提取或推断台词归属。重复文字有多种匹配时脚本拒绝猜测，在对应提取项补入核实后的 `source_start` 再执行。最后把局部配乐覆盖写入dialogue.json。更新现有索引前保留并恢复其有效设置与局部覆盖，不能用默认参数覆盖用户设置。

索引脚本更新已有文件时，未显式传入的配乐开关和时长上限沿用现值，并保留 `unit_music`；仅新文件采用默认开启与35秒。来源话语及其分配仍须按新稿重新核对，保留设置不代表旧单元范围仍然有效。

## 3. 当前输出合同与自然语言台词

完整交付严格采用所选 `output-music.md` 或 `output-detail.md` 的6.1—6.4节，不为程序添加栏目或固定统计行语法。配乐关闭没有全局声音标题；对白、OS、OV、环境声与拟音仍写在原有声音位置。项目参数填写实际总时长、单元数、成片镜头数及单元上限；这些数值按当前输出合同表达即可。

单元、时间窗、栏目和出现顺序照当前输出合同。台词与声音层次采用自然语言写清人物全名、原文、发声时间、声线、停连重音和口型；不要求话语U编号、JSON引号或另造表格。时间线只写语义节点，不重复完整台词。跨单元拆句保持原文顺序与标点，不重说字尾；连续音轨只在首次声音栏出现完整原文，后续说明接续时段与口型，实际音轨覆盖另行核对。

脚本在声音栏目按“人物全名＋话语类型＋完整发言”匹配，每次发言只消费一次；不以子串次数计数。因此长句里的“？”、“……”或短词不算另一句同内容反应的重复。原作同句重复必须对应不同来源ID，额外生成的重复发言仍报错。

跨单元拆句时在内部dialogue.json加入 `delivery` 列表，例如 `[{"id":"U001","unit":"G1","text":"不来"},{"id":"U001","unit":"G2","text":"了。"}]`。每项分配匹配对应单元的一次完整发言片段，按交付顺序拼接回来源全文；真实重复片段逐次分配，不要求文字全局唯一。不能为了消除标点误报而拆生成单元或改写台词。程序识别人物全名、可选时间与说/OS/OV等标记、括号内演绎说明，以及同一行中归属明确的多个带引号发言；未标类型但名称与引语明确的新人物也参与匹配。明确标为读法/演绎说明的引用与话语内部引语不另计发言。无法可靠解析的归属、未闭合引号/括号等列入报告的人工待核项；不以静态通过代替这些项目的人工确认，不退回子串计数。分配记录不能证明播放时刻、口型或语义归属正确。

## 4. 运行核对

在普通文件交付的授权范围全部编译完成后运行本技能自带的stdlib脚本，不依赖旧技能或联网。逐场创作复审检查本场与接点，不能将整集来源索引对尚未完成的主稿运行后误判后场台词缺失。需检查局部交付时，来源索引和主稿统计都明确限于该授权范围，保留该范围当前输出合同必要的全局及场景栏目：

```bash
python3 <本技能目录>/scripts/validate_storyboard.py <主稿.md> --source <source.txt> --ledger <dialogue.json> --report <checks.json>
```

实际调用时替换绝对路径并正确引用。脚本只读取主稿、来源和索引，仅向指定report路径写报告；拒绝将report写到输入路径。退出0表示所实现机械检查通过，1表示具体失败，2表示输入/格式错误。无Python或文件能力时完成相同人工核对，明确程序未执行。

机械覆盖：单元编号/时长/承载镜号，时间窗连续覆盖，焦段必填及同镜衔接，必需栏目/顺序/非空，项目统计、配乐开关与逐窗配乐行，以及声音栏目相对来源索引的原文拼接与发生次序。程序同时核对已识别发言的说话人和对白/OS/OV/旁白标签；语义归属、未识别表达、播放时间与口型仍须人工核对，不宣称程序已完整验证。来源哈希和文字区间同时校验，不能只拿模型自写清单互相比对。

不能机械确认：源稿所有发言的提取完整性与语义归属，未标识的散文引语是否被重复生成，物理空间/镜头可见性是否真实成立，表演感染力、笑点、配乐是否动人、自然语速、声音是否真的清晰、平台生成与音轨接缝。报告始终列出这些人工/成片待验项，不把静态通过包装为S+认证。

## 5. 修改与完成

修改先识别来源事实、导演决定还是实现路径发生变化，沿真实依赖更新对应镜头组、声音、光影、状态和必要后续；不重算无关场景。改变景别、机位、身体朝向或可见面时，同步核对场景摄影规则中涉及该镜的具体声明、场景空间、单元摄影栏、时间窗及起落状态，不能只修改时间线的景别名。独立生成的文字可能在不同栏目引用同一旧决定，此类冲突须按实际取景定向统一。最终主稿有改变就重跑机械检查，创作复核只针对改动及依赖。长任务按场保存到同一主稿，范围未完成不得改名为定稿或仅靠压缩后半段交付。局部任务只索引当前授权范围，不能因源快照含整集而擅自生成整集。
