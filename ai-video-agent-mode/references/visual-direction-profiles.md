# Visual Direction Profiles

本文件只在用户要求画面质感、灵动、唯美、现代剧质感、古风游戏质感，或自动题材识别命中时读取。它是轻量视觉路由，不增加运行阶段、输出字段或 Agent。

## 路由

先判断用户显式风格，再判断源文证据。优先级为：用户明确要求 > 源文明确视觉事实 > 本文件自动路由 > 通用电影化默认。源文台词中的风格词不触发路由。

可用 profile：

| 触发信号 | profile | 视觉重点 |
|---|---|---|
| 古风游戏、国风武侠游戏、武侠游戏质感 | `chinese_wuxia_game_cinematic` | 东方空间、人物轮廓、自然色、真实材质、武侠动作重量 |
| 写实古风、历史武侠、江湖烟火 | `grounded_historical_wuxia` | 动机光、旧损材质、低饱和、重心与惯性 |
| 写意古风、华丽武侠、诗意江湖、仙侠 | `painterly_elegant_wuxia` | 色彩分区、服装轮廓、山水层次、克制空气光 |
| 宫廷、府邸、朝堂、古装关系戏 | `period_court_cinematic` | 礼制空间、门窗层次、克制华饰、人物关系距离 |
| 现代剧、自然电影感、生活化质感 | `modern_natural_drama` | 现实光源、生活痕迹、自然表演、低幅环境活动 |
| 都市情感、职场、咖啡馆、夜车 | `modern_cinematic_variant` | 场景专属色卡、玻璃/金属/布料差异、移动光源 |
| 乡村、小镇、自然生活、家庭日常 | `rural_lived_in_naturalism` | 地域材质、天气痕迹、生活使用痕迹、自然纵深 |

只有命中强证据时才自动偏向古风游戏；“古代宫廷”默认走古装电影化，不自动加入江湖动作。没有明确风格时，按场景类型、剧情功能、情绪温度、时间天气和现实光源生成本场 profile，不把预设词原样投喂。

## 多证据自动适配

不要只看关键词。先为当前项目和每个场景提取证据卡：

`用户风格要求 | 时代与现实层 | 地点/建筑 | 人物身份与服装 | 道具/技术水平 | 动作物理 | 剧情功能 | 情绪温度 | 时间天气 | 现实光源`

每条自动证据必须能回指源文事实。按以下规则选择一个基础 profile：

- 用户明确要求或项目配置：直接高置信，除非与不可改变的剧情事实冲突。
- 自动适配：每个独立证据通道记 2 分；同一通道重复词只计一次。至少三个通道且总分 `>=6` 为高置信，两个通道且总分 `3-5` 为中置信，其余为低置信。
- 单个服装词、角色台词、比喻、情绪形容词或地点刻板印象不计分；明确的时代、技术或空间矛盾记 `-4`。
- 高置信可完整应用基础 profile；中置信只应用光源、材质和空间中被证据支持的层；低置信回到通用电影化默认，不猜题材。

基础 profile 之上最多叠加一个 `narrative_modifier`：

| 剧情证据 | modifier | 只改变 |
|---|---|---|
| 悬疑、试探、信息遮蔽 | `suspense_restraint` | 遮挡、留白、局部低照度和揭示顺序 |
| 亲密、重逢、关系缓和 | `intimate_warmth` | 人物距离、柔和反差、肤色与呼吸余波 |
| 喜剧错位、尴尬升级 | `comic_clarity` | 信息可读性、反应时差、明暗清晰，不增加卡通夸张 |
| 失落、离别、压抑 | `melancholic_distance` | 空间留白、冷暖距离和低幅环境余波 |
| 追逐、冲突、动作升压 | `kinetic_pressure` | 重心、方向、惯性和节奏，不自动变成武侠 |

时间、天气和现实光源只作为第三层场景变体，不改变基础题材。现代夜景不自动加入霓虹，乡村不自动变成暖黄怀旧，悬疑不自动染绿，古装不自动加入武侠/仙侠，唯美不自动增加雾、辉光或慢动作。

项目级 profile 默认跨场继承；只有时代、现实层、地点文化或用户要求明确变化时才做场景级覆盖。同一场景的情绪变化只调整允许的曝光、色温比例、构图距离和运动能量，不中途换基础 profile。

内部记录轻量解析回执：`base_profile | narrative_modifier | confidence(high/medium/low) | evidence_score | matched_evidence | contradictions | inherited_or_overridden | applied_layers | user_overrides`。它只供 Scene Lock 和审查消费，不进入 `full_prompt`、最终 Markdown 或新增 schema；证据不足时回到通用电影化默认。

## 共同视觉底座

所有 profile 都建立四层：

1. `light`：动机光源、方向、受光面、衰减、阴影曝光、肤色保护。
2. `color`：主色/辅助色/点缀色、色温关系、黑位、高光保护和跨镜连续。
3. `material`：两到三种剧情相关材质及不同反光，保留一到两项自然不完美。
4. `motion`：起态、触发、主体动作、环境响应、材质响应、余波落幅。

不要用“电影感、高级感、唯美、灵动”替代上述可见事实。游戏名只作内部别名，直接投喂正文写原创可执行事实。

## 场景生命合同

每个场景内部建立：

`动力源 | 常态环境运动 | 剧情触发 | 差速响应 | 静止锚点 | 余波状态`

单镜只选一个主动作、一个镜头路径或锁定机位，以及一条因果响应链。低风险镜的链内最多两个共享动力源的低幅响应；长对白、多人、道具转移、复杂支撑或腾空镜只保留一个。环境运动必须有因果：窗光随云层变化、车灯扫过脸侧、门开后冷光进入、杯面因落桌产生两次水纹、烛焰受风后墙影稍晚恢复。不要让所有层同步摇动，也不要每镜重复同一套“慢推+轻雾+衣摆”。需要人物个性化微动作、相位差或跨镜动静曲线时按需读取 `liveness-motion-grammar.md`。

动态提示词按 `起态 → 可见触发 → 响应 → 稳定落幅` 编译。落幅要保留呼吸、灯火、水纹、热气、远处人流或布料余动中的一项，但不得破坏下一镜可继承的硬状态。

## 光影增强

优先采用三层光影：环境基础光、人物独立表演光、剧情变化光。每处光影写清来源、方向、接收表面和阴影结果。彩色环境光只进入背景、衣物边缘、头发或有依据的脸部局部；脸、嘴和活动手保持中性或微暖受光。

现代场景优先使用窗光、顶灯、台灯、屏幕光、车灯、店招和玻璃反射；古风场景优先使用天光、檐灯、烛火、火盆、月光和湿地反射。增强光影不等于增加辉光、轮廓光、丁达尔光或大面积雾。

## 反 AI 感

每镜最多加入一到两项自然不完美：不均匀玻璃痕、磨损桌边、布料褶皱、断续雨痕、破碎积水反光、轻微背景占用、人物自然不对称。避免塑料墙、镜面泥地、均匀雨线、同步背景人物、过度磨皮、死黑阴影、过曝灯管和全场同一材质高光。

## 两个技能的消费方式

- `ai-video-agent-mode`：将 profile 写入 Visual Bible、Scene Lock、`static_aesthetic_contract`、`dynamic_aesthetic_contract` 和 `video_texture_contract`；直投正文只消费一个光影锚点、一个材质/空气锚点和因果链中最必要的一个运动响应。
- `jimeng-dialogue-performance-storyboard`：将 profile 写入全局影调索引和场景状态底图；每条直接提示词加入压缩视觉前缀、一个具体受光关系和一个因果环境响应，不新增最终 Markdown 字段。

## 信息主次

每镜先分四级：`must_render | important | metadata_only | drop_first`。`must_render` 永远优先台词/口型、人物身份与位置、动作因果、关键道具和稳定终态；`important` 只保留一个受光关系和一个剧情相关视觉增强；profile 判断、审美解释和质量分值留在 `metadata_only`；复杂运镜、额外空气层、第二材质与装饰性反光进入 `drop_first`。长对白、多人、道具转移或支撑变化镜先删 `drop_first`，再删低优先视觉增强，不得删硬事实或用更多修辞补偿。

## 质量闸门

生成前检查：场景是否有现实动力源；光影是否有落点；材质是否分层；镜头是否有信息收益；主体和环境是否有差速；同组是否重复构图/运镜/表演；长对白是否因质感词过多而挤压口型与终态。真实成片评估仍必须使用用户提供的 A/B 视频，不能用提示词或 Golden 文本假装视觉证据。
