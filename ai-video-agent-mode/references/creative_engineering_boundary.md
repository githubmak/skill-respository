# 创作主权与工程边界

本合同高于字段合同、验证规则、性能目标和导出便利性。发生冲突时，先保护大模型的剧情理解、
情绪分析、表演设计和镜头创作，再调整工程实现；不得为了通过验证而静默改写创作语义。

## 大模型主权

以下工作必须由大模型完成：剧情与潜台词理解、人物目标和关系变化、戏剧节拍、拆镜、Scene Lock
的创意设计、表演与情绪因果、人物调度、构图、景别、焦段、运镜、光影、色彩、材质、声音、
转场、镜头组节奏、Seedance 版本适配与提示词语义编译，以及对最终呈现效果的语义复审。

工程代码不得通过关键词、正则、固定模板、镜号特例、字段评分或启发式删句代替以上判断。格式或长度不合格时，
返回结构化 `CREATIVE_REWRITE_REQUIRED`，由大模型在锁定事实内重新创作。
工程在阶段间传输创作对象时必须完整保留模型已写入的全部字段，不能以字段白名单、所谓上下文压缩或固定
创作 Schema 删除未知字段，也不能自动注入节拍归属、镜头组、运镜类型或审美默认值。

## 工程职责

工程代码只执行无创作判断的工作：文件与编码、配置、ID、时长和字符计数、Schema、逐字台词核对、
哈希与 provenance、缓存、并发、心跳、断点恢复、版本、确定性合并、排版及 Markdown/XLSX
导出。运行截止、批次超时、队列续派、字节/字符/镜数和平台可提供的 token 遥测也属于工程职责。
工程层可以拒绝不合法数据，但不能把不合法的创作内容改写成另一份语义。

## 协作边界

- Scene Lock：大模型创作和解释，工程层只冻结文件版本、记录引用与报告事实差异。
- 连续性：工程层提供事实差异，大模型决定如何在画面、表演和镜头中解决。
- 时长：工程层测量，大模型决定拆镜、节奏和语义压缩。
- 字数：工程层只计数；超限时由大模型重写，工程层不得去重、选句或删除。
- 首轮质量：Orchestrator 与 Master 必须把第一次落盘内容作为可直接交付的最终候选；模型在落盘前自行完成导演判断，工程不得用评分表或字段配额代替。
- 审片：Editor 只做独立验收、说明创作因果并指定最早责任阶段，不直接补写、拼接或局部润色提示词。
- 修订：全局理解问题回 Orchestrator 重新创作，单镜导演实现问题回 Master 整体重做该镜；工程层只传递模型给出的责任阶段、镜头 ID 和事实错误。
- 质量：工程层检查硬约束，大模型审查剧情、情绪、表演、审美和镜头效果。
- Seedance：大模型直接输出目标版本语义；工程只核对目标版本字段存在、长度和原样导出。

## 修改门禁

每项修改必须先声明：根因、受影响所有权、是否改变创作语义、通用性和真实 E2E/A-B 验证方式。
禁止按项目、角色、镜号或单次错误文本打补丁。新增能力若不直接提高最终呈现、源文保真、平台可执行性
或运行可靠性，不得进入基础主链。
