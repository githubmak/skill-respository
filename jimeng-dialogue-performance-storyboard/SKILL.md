# 即梦剧情表演分镜

## 最高优先级

把最终成片质量作为唯一创作目标。大模型负责所有会改变观众体验的决定：理解原文、拆镜与时长分配、节奏、表演、情绪、调度、机位、景别、运镜、焦点、光影、影调、色卡、Seedance 表达和创意修订。工程脚本只核验可客观证明的事实：文件可读性与哈希、原文声音逐字和顺序、编号、时长算术、字段、长度、路径、几何计算、staging、审核状态、提升状态与 manifest。

任何脚本、模板或旧规则若用关键词、评分、配额或词面回收判断创意，要求固定运镜数量、签名镜数量、情绪链格式、色词位置，或自动选择创意修复，均不得进入主流程。工程失败只返回事实；由大模型重新判断如何修正。

## 路由与读取

1. 解析本技能目录为 `<skill_root>`，运行 `python3 <skill_root>/scripts/route_task.py generate --source <源文> --seedance-target auto|2.0|2.5|both --compact --report <reports>/route.json`。本调用就是唯一源 intake；不得再运行 `source_gate.py`。`auto` 确定性解析为 2.0 兼容基线，活动界面已确认支持 2.5 时显式选择 2.5。
2. 创作前只读取路由的 `read_first`。先完整通读源文并形成场景理解，再由模型从 `creative_reference_catalog` 按当前难点选择最少资料；源文关键词、风险信号和说话人数不得自动决定创意参考。
3. 写交付 Markdown 前再读取路由的 `read_before_delivery`。用户明确提出风格或质感时才读视觉资料；复杂表演、材质、调度、摄影机或真实生成失败分别选择一个最相关资料，解决后停止扩读。

## 主流程

1. 使用 `route.json` 中已经完成的 source intake，并完整通读源文。建立最小事实连续性台账，只冻结人物、事件顺序、因果、台词/OS/OV/系统音、位置、躯干/头部朝向、视线目标、站坐支撑、手部与道具归属、边界和跨场状态；另把摄影机轴侧、画面左右与可见面记为当前机位投影，不能把换机位误写成人物转身。简单单人静态镜可省略无争议的朝向细节；所有多人镜即使简单也至少记录人物槽位、躯干朝向、视线目标和画面左右，转身、换位、正反打或遮挡风险镜再完整记录头部、可见面和首尾状态。源文哈希未变时复用。
2. 按 `runtime-core.md` 完成导演设计。先为每场在内部压缩一条因果主线，再决定拆镜、表演、调度、摄影机弧、光影和色卡；简单场景一句话后直接创作，只有误解、试探、隐瞒、反转、多人反应传播或复杂状态转换造成真实理解断点时，才展开相关节拍。因果主线区分原文事实、合理推断与导演选择，不写入固定交付字段，不生成 JSON，不逐镜重复。风险适配只能发生在创意方案之后。
3. 空间工具直接选择 `none|2d|3d|both`：无歧义的简单镜头用 none；平面站位、身体朝向、边界、轴侧和视锥用 2D；站坐支撑、躯干与头部不同向、视线目标、手部接触、道具高度、遮挡或真实投影用 3D；只有两者提供不同证据时用 both。人物在同镜发生转身、换位、起坐或视线关系重构且确需参考时，为同一 `shot_id` 建立 `physical_phase=start|end` 两个 3D 物理状态；摄影机单独运动仍使用 camera `path`，两种首尾机制不得混写。人物与摄影机同时复杂运动时优先拆镜或使用用户已有且已审核的参考视频，不为证明流程完整而强制生成白模视频。工具硬阻断仅限穿越实体、合同矛盾和不可达接触；构图比例、面向容差、边距与标签碰撞只给 advisory。3D 使用中性工程材质与中性灯光，相同物理状态的多机位复用场景。所有未审资产只写入 `staging/`。投喂图命名为 `镜头号_即梦_2D_空间关系.png` 或 `镜头号_即梦_3D_空间关系.jpg`；摄影机路径或人物物理首尾均使用 `_start`、`_end`，审核图再加 `_审核`，状态和机位索引只留在报告中。空间参考图是可选证据，不是直投前置条件：直投提示必须脱离参考图独立成立；只有本镜列出已审核参考素材且用户明确选择上传时，才使用“若上传该图……”的条件句。未上传时，文字中的人物位置、机位、姿态、支撑、持物和接触关系仍必须完整有效。低模 2D/3D 图只负责空间、机位、姿态、支撑、持物和接触，不负责人物外貌、服装、材质、色彩、光影或成片风格，不得把“参考图中……”写成无条件要求。
4. 使用 `output-template.md` 撰写 Markdown。每镜完整直投代码块按主要内容分行，固定顺序为 `主体与起态`、`动作时间线`、`台词`、`摄影机`、`焦点`、`视觉控制`、`声音设计`、`稳定结尾`；四项核心必填，其他四项只在有实际控制价值时出现。所有多人镜在 `主体与起态` 至少用可见语言写具名人物槽位、躯干朝向、视线目标和画面左右；转身、换位、正反打或遮挡风险镜再分别写双脚、头部朝向、可见面和首尾状态。头身同向时合并，不能只写“面对”。`动作时间线` 只说明发生变化的身体部分及保持项，`稳定结尾` 重述变化后的唯一物理终态和画面投影。台词/OS/OV/系统音只在 `台词` 分句原样出现一次。先为每场建立 `VC-Sn`，再把需要的光源、冷暖、曝光、材质综合色彩和肤色直接展开到逐镜 `视觉控制` 句；最终直投提示不得出现 `VC-Sn`、`同上镜`、`继承前镜` 或 `沿用上一镜`。无物理变化时保持光源、冷暖、曝光和材质综合色彩，变化时写触发、影响范围、保持项与新稳定态。
4a. 生成后先做空间语义自检：`主体与起态` 禁止裸用无参照的“侧后”“深景”“稍后”等导演速记，必须补出相对于哪个人物或固定物、摄影机视角下的画面左右/前后和必要的视线目标；摄影机句中的“从某物侧后方拍”只有在机位参照物已具名时才可使用。随后运行交付校验，出现 `PROMPT_SPATIAL_AMBIGUITY` 必须回写直投提示后再进入审查。
5. 保存后运行 `validate_delivery.py --source <源文> --storyboard <输出.md> --seedance-target <目标> --compact --report <reports>/delivery.draft.json`。它只做确定性交付校验，不判断创意优劣。失败时只修复客观交付错误，不因门禁改写导演方案。
6. 读取并执行 [review-pipeline.md](references/review-pipeline.md)。由大模型只依据源文和最终直投提示反向还原触发、人物理解与策略、听者反应及场景新状态，再完成相邻镜物理与视觉基线对照；存在图片或视频时必须查看真实画面。设计或视觉不通过时定位第一层根因并重选、拆镜或重写。
7. 审核通过后创建 review attestation manifest；它只声明审查结论并绑定文件哈希，不证明审查者身份或审查质量。纯文本交付使用 `visual_review=NOT_APPLICABLE`；存在视觉资产时必须为 PASS 才能 FINAL。无需单独运行 verify，`validate_delivery.py --final` 会直接复核 manifest、哈希和正式资产。

## 创作与工程边界

- 模型必须主动完成表演、空间、摄影机和视觉设计。场景 `VC-Sn` 只在内部锁定跨镜物理与调色连续性，逐镜视觉控制必须独立写出该构图所需的可见光源、综合色彩、曝光和肤色，不把基线编号投喂给 Seedance；不规定颜色答案、百分比或固定光型。二维/三维工具只能渲染模型已决定的状态。
- 时长工具只能给出原文声音字符数、实测音频时长或容量提示；拆在哪里、是否留停顿、是否拆动作与台词由模型决定。
- Seedance 适配只消除指代与路径歧义，不替导演选择机位、焦点或终态。避免“摄影机跟随手指从叶片落到人物脸”这类共享路径句，分别写摄影机、焦点、手指和叶片的实际状态。
- 因果主线只约束观众应当读懂的事件与关系变化，不规定拍法、景别、表演术语或直投句式；不做复杂度评分、固定节点数量、因果关键词门禁或永久角色缓存。原文故意保留真相时，只设计人物当下相信什么和观众应保留的疑问，不把推断升级为事实。
- 不生成含创意决策的前置 `scene_contract.json`，但必须保留最小事实连续性台账；不从成稿反向恢复创意合同，不逐镜运行创意正则，不用重复字段证明同一事实。
- 技能目录不保留旧创意正则、合同恢复、逐镜修复器或其兼容入口。若外部旧文档提到这些工具，视为已废弃，不能恢复到主流程。

## 交付硬事实

原样保留人物身份、事件顺序、因果和全部台词/OS/OV/系统音；每镜 `>0s` 且 `<=15s`。普通直投提示建议不超过 500 字，复杂镜建议不超过 650 字，绝对上限 700 字。两版本必须共享镜号、时长和 `台词` 原文。正式目录不得引用 `staging/` 资产，未审核线稿不得进入正式目录或 Seedance 参考位。

修改技能后运行系统 `quick_validate.py`，并用未见过的完整剧本前向测试；成功标准是成片设计质量、语义清晰、声音可执行、审核有效和无循环修补，不是创意正则通过率。
