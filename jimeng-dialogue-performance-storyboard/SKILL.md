# 即梦剧情表演分镜

## 最高优先级

在原文事实、因果、人物知识权限、空间连续性和 Seedance 可执行性这些硬约束内最大化成片质量。大模型负责所有会改变观众体验的决定：理解原文、拆镜与时长分配、节奏、表演、情绪、调度、机位、景别、运镜、焦点、光影、影调、色卡、Seedance 表达和创意修订。工程脚本只核验可客观证明的事实：文件可读性与哈希、原文声音逐字和顺序、编号、时长算术、字段、路径、几何计算、staging、审核状态、提升状态与 manifest。

剧情因果优先于表演数量和镜头技巧。人物动作、反应、摄影机变化、转焦、环境运动和光影变化必须帮助观众读取事件、目标、关系、信息、空间或余波；不能为了“有表演”“有运镜”“有氛围”增加无意义举动。事实基线闭合后，主动寻找能放大现有转折的构图、观看位置、摄影机/焦点响应、光影层次和材质对比；这种视觉提升只能放大已发生的事实，不得新增剧情关键人物、互动道具、事件、结果、人物知识、改变因果的实体、空间边界或无来源的时间跳跃。允许补足不参与因果、不可被拿起或触碰、不会改变空间拓扑的背景陈设与材质细节。静止、压住反应、延迟反应和不移动摄影机都是完整导演选择。不得强制所有情绪套用蓄力、临界、释放三段式，也不得用固定动作、固定拍法或固定颜色替代对当前人物和剧情的判断。

控制强度按固定优先级分配：`叙事意图与观众应理解的变化 -> 本镜主视觉核心 -> 为完成该变化所必需的动作因果、接触与结果 -> 会影响理解或生成稳定的空间约束 -> 有剧情意义的微表情 -> 其他细节表演、环境动态与装饰`。先把高层级写清，再判断低层级是否真正提供新证据；低层级不得挤压叙事意图、主视觉核心、台词和稳定结果。普通对白与生活动作不使用逐关节、逐步态、逐帧姿态或类似3D骨骼动画的控制语言。只有手部交接、起坐支撑、危险遮挡、转身换面、复杂接触、人物身份易漂移或已有真实生成失败时，才增加最少必要的身体部位与运动阶段约束。微表情可以被精确设计，但必须表现人物判断、控制策略、情绪泄露或关系变化，不能成为装饰性表演清单。

任何脚本、模板或旧规则若用关键词、评分、配额或词面回收判断创意，要求固定运镜数量、签名镜数量、情绪链格式、色词位置，或自动选择创意修复，均不得进入主流程。工程失败只返回事实；由大模型重新判断如何修正。

硬约束只定义不可发生的错误，不定义唯一正确拍法。先在原文事实边界内自由形成导演方案，再用空间、时长、声音、连续性和 Seedance 语义检查它能否执行；不得让审查表、参考示例、风险术语或“最少充分控制点”提前替模型选择构图、表演、运镜、焦点、光影和节奏。候选发散、直觉判断、反常规构图、长时间静止、突然切近、留白或复杂连续调度均由模型按当前剧情自由选用，不设候选数量、复杂度等级或创意得分。审查只指出事实冲突、因果断裂、信息不可读和执行矛盾；同样正确的多种导演解不得因不符合示例外观而被判失败。

整场导演设计完成后的视觉增益复核只执行一次，即主流程第 2 步中的复核。后续信息预算、Seedance 适配、色卡和审片规则只检查、翻译或删减已经选定的视觉方案，不再次追加运镜、光效、材质变化或画面记忆点。

## 默认提示词密度

默认采用接近用户示例的导演表达：用一个稳定空间锚点建立关系，用一条完整画面描述完成剧情节拍，用必要的摄影机路径组织观看，再用一句光影与色卡结果收束。空间高风险镜在语义上闭合 `空间锚点、运镜轨迹、情绪传导、互动逻辑`；普通对白镜不机械展开四层，也不把审片台账复制进直投提示。

每镜只显式锁定会改变剧情、关系、空间、动作归属、声音权限或稳定结果的控制点。自然倾听、呼吸、眨眼、轻微重心调整、衣发随动、惯性、说话中的自然目光与次级环境运动默认交给 Seedance；只有原文明确、构图依赖、容易漂移或真实生成失败时才追加。可见对白默认写清说话者、关键起说触发和听者最终反应，不逐句规定闭口、口型切换、每次转眼和每个接收瞬间；抢话、多人同时可见、OS/OV、电话、画外声或权限易错时再精确控制。

提示词以“足够让模型不误解”为停止点，不以“能继续补充”为继续条件。重复空间、光色、身体和尾态事实合并成自然短句；焦点、声音设计和复杂摄影机无实际观看价值时省略。简洁不得删台词、决定性动作、人物关系、必要锚点和剧情结果，也不得把镜头压成通用的“人物说话并做出反应”。

## 路由与读取

1. 解析本技能目录为 `<skill_root>`，运行 `python3 <skill_root>/scripts/route_task.py generate --source <源文> --seedance-target auto|2.0|2.5|both --compact --report <reports>/route.json`。本调用就是唯一源 intake；不得再运行其他源文门禁入口。`auto` 确定性解析为 2.0 兼容基线，活动界面已确认支持 2.5 时显式选择 2.5。
2. 创作前只读取路由的 `read_first`。先完整通读源文并形成场景理解，再由模型从 `creative_reference_catalog` 按当前难点选择最少资料；源文关键词、风险信号和说话人数不得自动决定创意参考。
3. 写交付 Markdown 前再读取路由的 `read_before_delivery`。用户明确提出风格或质感时才读视觉资料；复杂表演、材质、调度、摄影机或真实生成失败分别选择一个最相关资料，解决后停止扩读。

## 主流程

1. 使用 `route.json` 中已经完成的 source intake，并完整通读源文。建立最小事实连续性台账，只冻结人物、事件顺序、因果、台词/OS/OV/系统音、位置、必要朝向与视线、站坐支撑、手部与道具归属、边界和跨场状态；另把摄影机轴侧、画面左右与可见面记为当前机位投影，不能把换机位误写成人物转身。普通互动镜只记录理解叙事和主视觉核心所需的人物槽位、关系方向、视线目标、支撑和道具归属，不建立逐关节或完整身体部位清单。转身、换位、正反打、遮挡、接触、起坐或已有转正失败的风险镜，才补充能消除当前歧义的最少身体特征、双脚支撑和首尾状态；完全没有争议的状态不重复记录。源文哈希未变时复用。
2. 按 `runtime-core.md` 完成导演设计。先为每场在内部压缩一条因果主线，并为每个主要人物建立从入场状态到场末余波的表演弧，再决定剧情节拍、镜内调度、摄影机弧、光影和色卡；简单场景可以简写，但关键对白必须闭合可访问触发、人物当下判断与控制方式、情绪泄露、台词状态、正确听者反应和镜尾余波。完成事实与表演可读性后，再做一次视觉增益复核：比较静止或运动、远近或留白、遮挡或显露、焦点先后以及光源和材质的层次，选择能让当前关系、证据、权力或情绪更有辨识度的一种表达；不要求每镜复杂，也不为满足形式增加变化。逐镜确认观众得到什么新信息、人物关系或目标怎样变化、哪个物理状态被建立，或为什么需要有意维持尚未变化的压力；没有剧情、关系、信息、动作准备/完成或观看节奏收益的动作与镜头变化删除。完成自由导演方案后再做场级节奏诊断：沿时间线比较每个剧情节拍给观众带来的变化、必要读取时间和上一节拍留下的余波，识别无递进重复、已读懂后仍停滞、过程挤压关系变化或转折来不及落稳；不得预设整场目标时长，也不得按做饭、行走、递物等动作类型直接判定为“程序过程”。因果主线、表演弧与节奏诊断区分原文事实、合理推断和导演选择，不生成 JSON，不成为正式交付字段，不用情绪标签替代可见表演。风险适配只能发生在创意方案之后。

   边界对峙、多人调度、连续运镜或锚点构图等空间高风险镜，创作时再内部闭合四层：`空间锚点 -> 运镜轨迹 -> 情绪传导 -> 互动逻辑`。空间锚点冻结不会随镜头移动的实体、边界和人物物理槽位；运镜轨迹写清起落机位、参照、方向、速度感、触发与观看收益；情绪传导从可访问刺激出发，说明压力怎样在人物间递进或收束；互动逻辑闭合发起动作、接收、反应和稳定结果。四层必须彼此兼容，并分别落入既有的 `主体与起态`、`动作时间线`、`摄影机/焦点` 和 `稳定结尾`，不得新增机械交付字段，也不得要求所有镜头都套用四层长描述。

   导演方案确定后才做 Seedance 执行翻译。先写一个接近示例密度的连贯镜头：必要空间锚点、完整剧情节拍、主要表演与互动、必要运镜、光影结果和剧情落点；再只为真实歧义补控制。原文明确规定的细节、人物专属表演和有观看收益的视觉设计必须保留；非剧情关键的逐关节协调、步态补间、惯性缓冲、衣发随动、说话中的自然目光和次级环境运动留给模型完成。去掉抽象风格词后剧情仍应可还原；若保留事实后画面只剩通用人物说话或站立，补回服务同一节拍的导演证据，但不把释放出的提示预算重新填满。

### 拆镜核心规则

最终镜号按 `完整剧情节拍` 拆分，不按动作子步骤拆分。每镜必须同时满足：

- 观众能用一句话复述本镜完成的剧情变化、关系变化或空间信息变化；
- 本镜有一个主视觉中心，其他人物、道具、焦点和环境变化都服务于该中心；
- 镜内动作可以包含 `触发/起因 -> 连贯运动或表演 -> 反应/结果`，不得把其中的抬手、转头、拿物、走步、换手、落座、起身或单次焦点变化自动拆成新镜；
- 人物换位默认属于镜内调度。只要换位仍服务同一剧情节拍、摄影机可以连续记录起点和终点、空间关系可读，就不拆镜；
- 视觉中心可以随同一剧情节拍发生受控的视线、焦点或摄影机交接，但不能同时设置两个同等重要且互不从属的观看任务。若两个视觉中心都必须独立完成，先判断是否已经形成两个剧情节拍，再决定拆镜；
- 每镜硬上限为 `15s`。台词或 OS 未超过 `15 秒` 时，默认保持在同一镜内；超过 `15 秒` 时，才允许按语义停顿、人物判断变化、听者反应或明确剧情节点拆分，不得按字数或动作数量机械切断。15秒是上限，不是目标时长，不得为了接近上限补写无意义的细微动作、神情或环境摆动；镜头完成剧情节拍后即可结束。
- 不因“需要展示更多动作”“需要一个新景别”“需要一次转焦”“人物跨过门槛”或“道具换到另一只手”单独拆镜。只有当这些变化同时造成新的剧情结果、关系状态、空间拓扑或独立观看任务时，才构成拆镜依据。
- 设计顺序必须先确定本镜的叙事意图和主视觉核心，再决定必要动作、摄影机、焦点和光影；微表情在确有判断或情绪泄露时加入，其他细节表演和环境元素最后考虑。不得先写满动作、表情、身体部位和环境变化，再反向寻找它们的剧情用途。

这里的“镜”是正式交付的剧情节拍单元，不等同于内部动作清单。内部可以记录更细的动作顺序、空间锚点和连续性状态，但这些细节必须优先收进本镜的 `动作时间线`、`摄影机`、`焦点` 和 `稳定结尾`，不能为了审查方便扩张为更多镜号。后续如何把多个镜头编排为生成片段不属于本技能的拆镜决策。
3. 空间工具只选择 `none|2d`：无歧义且不需要辅助证明的镜头用 `none`；人物平面站位、躯干朝向、边界、轴侧、摄影机位置与视锥需要辅助证明时用 `2d`。二维线稿是位置参考图，不承担头部朝向、视线、站坐支撑、手部接触、道具高度或真实透视投影的证明职责；这些事实必须在直投提示中使用具名人物和具体锚点写清。若人物与摄影机同时复杂运动，或二维图和文字仍不能单义表达转身、换位、起坐、接触、遮挡等关系，先尝试在同一完整剧情节拍内用连续调度表达；只有因此产生独立剧情结果、独立观看任务或无法执行的空间矛盾时才拆镜，必要时再使用用户已有且经过真实画面审核的关键帧/参考视频。工具硬阻断仅限穿越实体、合同矛盾和被实体阻断的视线；构图比例、面向容差、边距与标签碰撞只给 advisory。所有未审二维资产只写入 `staging/`，投喂 PNG 固定命名为 `镜头号_即梦_2D_空间关系.png`；SVG 和审核图只用于审查，不能进入参考位。空间参考图是可选证据，不是直投前置条件：直投提示必须脱离参考图独立成立；只有本镜列出已审核 PNG 且用户明确选择上传时，才使用“若上传该图……”的条件句。未上传时，文字中的人物位置、机位、姿态、支撑、持物和接触关系仍必须完整有效。二维图只负责位置、躯干平面朝向、边界、轴侧、摄影机与视锥，不负责人物外貌、服装、姿态细节、材质、色彩、光影或成片风格，不得把“参考图中……”写成无条件要求。

   明确区分世界空间事实与当前机位投影：门槛、桌心、地砖缝、道路中轴、亭柱、御案等可以是固定世界锚点；“画面左/右、几何中心、前后遮挡”是随机位变化的投影结果。固定机位可以锁人物画面槽位，移动机位则必须允许非中心物体的屏幕投影和阴影按透视自然变化，不能把“世界位置不动”误写成“所有物体画面位置不动”。量化轨迹时核对角度、角速度、距离、速度和镜头时长是否相容；与人物动作合同发生矛盾时先重选轨迹或动作，不用负面提示掩盖。
4. 使用 `output-template.md` 撰写 Markdown。每镜代码块保持 `主体与起态`、`动作时间线`、`台词`、按需 `摄影机/焦点`、`视觉控制`、按需 `声音设计`、`稳定结尾` 的既有顺序。五项核心必填只要求语义闭合，不要求等量篇幅：`主体与起态` 用一个锚点句建立当前关系，`动作时间线` 用一段连贯画面描述完成剧情节拍，`台词` 原样保留，`视觉控制` 用一个光影色卡句给出当前结果，`稳定结尾` 只写真正改变或必须继承的落点。普通对白不逐句编排闭口、接收、转眼、焦点与闲置肢体；抢话、多人传播、OS/OV、电话、画外声、交接、越界、遮挡或已有失败时才补充相应控制。多人关键动作使用具名人物避免归属歧义；自然呼吸、目光微调、重心、衣发和说话补间留给 Seedance。摄影机、焦点和声音没有独立观看价值时省略。内部台账、基线编号和审片说明不得进入正式 Markdown。
4a. 生成后先做空间语义自检：`主体与起态` 禁止裸用无参照的“侧后”“深景”“稍后”等导演速记，必须补出相对于哪个人物或固定物、摄影机视角下的画面左右/前后和必要的视线目标；摄影机句中的“从某物侧后方拍”只有在机位参照物已具名时才可使用。随后运行交付校验，出现 `PROMPT_SPATIAL_AMBIGUITY` 必须回写直投提示后再进入审查。
4b. 逐镜做信息与动作预算审查，不统计字符数。每镜对应一个完整剧情节拍和一个主导观看任务；允许次级反应、情绪泄露和镜尾余波共同完成该转折。只显式保留删掉后会损失剧情、关系、情绪证据、空间可读性、动作归属或观看节奏的控制点；自然补间不因“还可以写”而加入。只有出现两个无法从属的观看任务、新剧情结果、关系状态或空间拓扑时才拆镜。台词或 OS 不超过 15 秒时，不因动作、焦点、景别或人物换位机械拆镜；超过时按语义节点和容量拆分。时长仍按声音、表演/动作、摄影机/焦点三条并行轨道取最长值，只追加不可重叠动作，并把约 `1s` 自然留白与已有尾势合并计算。
4c. 再做一次整场节奏反向审片，但不采用固定修订顺序。沿时间线检查每个镜头是否完成了一个可复述的剧情节拍，是否在单一主视觉中心内完成触发、连续动作、反应或结果，是否因动作步骤、人物换位、焦点变化或景别变化被错误拆细，是否混入了无意义的细微动作或神情。只有出现新的剧情结果、关系状态、空间拓扑或无法从属到同一主视觉中心的观看任务时，才保留新的镜号；台词或 OS 不超过 15 秒时，不因过程性动作或摄影变化新增镜头；任何镜头不得超过 `15s`。重复若形成举证升级、压力累积、喜剧节拍、悬念延迟、角色习惯或动作完成证据，必须保留其有效差异，但应优先放在同一完整节拍镜内表达。不设置场景秒数、镜头数、比例或动作类别配额。`稳定结尾` 是必须可验证的尾态，不是独立耗时项目；约 `1s` 自然留白已经在最终时长中统一计算，不能再因字段存在额外加时。
5. 保存后运行 `validate_delivery.py --source <源文> --storyboard <输出.md> --seedance-target <目标> --compact --report <reports>/delivery.draft.json`。它只做确定性交付校验，不判断创意优劣。失败时只修复客观交付错误，不因门禁改写导演方案。
6. 读取并执行 [review-pipeline.md](references/review-pipeline.md)。由大模型只依据源文和最终直投提示反向还原触发、人物理解与策略、听者反应及场景新状态，再完成相邻镜物理与视觉基线对照；存在图片或视频时必须查看真实画面。设计或视觉不通过时定位第一层根因并重选、拆镜或重写。

   反向还原只验证源文保真、因果可读、人物知识权限和执行唯一性，不把审片者偏好的构图、表演或镜头语言当作答案。相邻镜确属同一连续动作或情绪余波时，检查是否自然继承视线、屏幕方向、人物距离、道具、声音、光态或未完成动作中的任一有效入口；由模型选择最合适的交接证据，不设“每镜至少一种”的配额。修改既有分镜时只冻结源文事实、已确认物理状态和仍有叙事价值的导演核心，允许大模型重想低价值演绎；不得以提高稳定性为由静默削弱原有情绪峰值、画面记忆点或视觉层次。
7. 审核通过后创建 review attestation manifest，并通过 `--review-report <reports>/design-review.md` 单独绑定审片报告哈希；报告仍留在 `reports/`，不进入正式输出或投喂素材。manifest 只声明审查结论并绑定文件哈希，不证明审查者身份或审查质量。纯文本交付使用 `visual_review=NOT_APPLICABLE`，证据范围为 `TEXT_ONLY`；只审核线稿、关键帧或其他图片参考时为 `REFERENCE_REVIEWED`；交付视频并通过真实画面审片时才为 `RENDER_REVIEWED`。无需单独运行 verify，`validate_delivery.py --final` 会直接复核 manifest、报告、哈希和正式资产。

## 空间锁定与防转正

- 空间控制只服务叙事意图、主视觉核心、人物关系读取和生成稳定。普通双人互动、单人面对道具/桌面/门口/画外声源时，优先用具名人物、相对位置、关系方向和视线目标表达，不默认展开身体部位或关节链。只有正反打、遮挡、侧背构图、转身换面、起坐支撑、复杂接触或已经出现转正/换面失败时，才使用最少必要的物理特征锚定消除歧义。
- 每个会影响剪影、遮挡、关系读取、口型或人与物因果的可见人物只记录当前必要锚点；无关背景人物和不会改变主视觉核心的身体细节不写。耳朵、肩背、后脑、胸口、双脚和可见面仅在当前景别确实可见且能解决具体风险时使用，不能组成固定模板或逐关节3D骨骼描述。
- “正面可见”只说明摄影机看到的表面，不等于人物面向镜头；“侧面/侧后/背面”不能单独承担高风险空间事实。若目标是桌面、文件、门口或画外声源，写出具体注视点，避免只写“看向旁边”。
- 关键朝向应靠近人物槽位和起态出现，动作导致身体、头部或视线改变时在时间线中二次确认变化后的可见特征。这里的前置与二次锚定是可读性启发，不假定平台存在公开的词序权重，也不要求无意义重复。
- 正向物理事实优先；负面提示词只在本镜确有转正、换面或视线漂移风险且已有生成证据时追加。不要默认写“全程不转向镜头”；若剧情需要回头、转身或正面揭示，必须写清触发、身体阶段、摄影机看到的表面和稳定终态。
- 审片时分别回答：人物身体真实朝向谁/什么、头部和视线落向哪里、摄影机实际看到哪一面、是否发生了真实转身，还是仅仅换机位造成可见面变化。物理特征锚定用于提高 Seedance 可读性，不得替代表演策略、关系变化或运镜创意。

## 剧情推进、反应与声音边界

- 情绪判断从人物实际能看见、听见、触碰或已经知道的事实出发，再判断人物此刻目标、误解、控制方式和泄露渠道。人物不能响应自己无权知道的信息；反应发生在刺激抵达之后，允许符合人物策略的延迟、压制、误判或不反应。
- 动作只在以下至少一种情况成立时保留：执行或准备剧情行为，改变人物/道具/空间状态，传递或遮蔽信息，体现当前人物的关系策略或压力泄露，引发另一人物的因果反应，建立剪辑与连续性，或形成对当前转折有明确观看收益的余波。自然呼吸和生活动作可以很轻，但不能成为防止画面静止的填充物。
- 情绪曲线由原文决定。确有积蓄、临界和释放时可使用该结构；持续压抑、延迟反应、突然认知、喜剧错位、麻木、克制缓和或无明显释放时，按真实形态设计，不补造临界点和爆发。
- 可见对白属于画内可听声，并由具名说话者驱动口型；画外对白、门外声、电话或广播只有处于实际传播范围内的人物能够听见。OS、旁白和默认 OV 只向观众呈现，不驱动口型，也不能成为其他画内人物的触发。系统音必须逐镜明确可听者范围；未获授权的人物保持不知道，不产生对应反应。
- 每条声音在内部确认主体、通道、可听范围、口型主体和获准反应者，但只把可能被 Seedance 误解或承担剧情转折的部分写入 `动作时间线` 或按需 `声音设计`；普通近距离连续对白不重复口型、闭口和“对方听见”等常识。
- 摄影机变化必须改变观众对信息、关系、权力、距离、空间、动作证据或情绪余波的读取，并优先把关键事实转化为有辨识度的观看位置：证据出现可让镜头靠近，关系疏离可让空间和留白扩大，认知转变可让焦点或遮挡发生有因变化，动作完成可让落幅留下结果。推镜、拉镜、横移、环绕、转焦和切镜没有固定情绪含义；人物动作先服从剧情，摄影机再选择最能显露该动作与反应的位置。静止构图已经足够时不添加运动，但也不能只因生成风险而放弃有明确观看收益的运动。
- 影调从时间天气、真实光源、空间结构、人物肤色和剧情相关材质推导。全场保持光源方向、综合色彩、曝光、黑位、高光和肤色逻辑连续；在这些事实不变的前提下，优先通过受光面、前后景亮度、材质反差、局部反射、负空间和真实环境动态提升画面美感。只有光源、遮挡、时间、天气、空间或明确主观视角变化才改变；不得为了“更美”新增无来源光源、颜色、雾、粒子、装饰或人物动作。冷暖、明暗和饱和度可以帮助观看，但不能直接替代悲伤、亲密、悬疑或爆发的表演判断。

## 创作与工程边界

- 模型必须主动完成表演、空间、摄影机和视觉设计。完整跨镜光色逻辑保留在全局视觉基线与审片报告；逐镜 `视觉控制` 只提取当前构图最有生成价值的主光方向、综合色彩/材质落点和曝光或肤色结果，用一个紧凑句表达，不重复完整调色清单。二维线稿工具只能渲染模型已决定的平面空间状态。
- 时长工具只能提供实测音频时长或容量提示；没有实测音频时，模型按声音、人物表演/动作、摄影机/焦点三条并行轨道判断最长基础时长，再加不可重叠动作与约 `1s` 自然留白。单镜拆分优先服从完整剧情节拍和主视觉中心，不按动作步骤、人物换位或焦点变化拆分；台词或 OS 不超过 `15s` 时默认保持一镜，超过 `15s` 才按语义节点拆分。每镜硬上限为 `15s`，但不得为达到上限补写无意义的细微动作或神情；剧情节拍完成、结果可读即可提前结束。拆在哪里、哪些事件能够重叠、是否需要额外停顿由模型依据当前表演决定，不用字符数推导语速或阻断交付。
- 摄影机使用米数、角度、角速度或线速度时，必须先做基本可行性核对：`环绕耗时=扫过角度/角速度`，`位移耗时=距离/速度`。总轨迹、停留、台词、动作和自然留白必须共同落在镜头时长内；例如 `5°/s` 完成 `360°` 环绕需要 `72s`，不能写入默认 `15s` 单镜。数值只在减少歧义时使用，不能替代可见起幅、路径、落幅和观看收益。
- Seedance 适配只消除指代与路径歧义，不替导演选择机位、焦点或终态。避免“摄影机跟随手指从叶片落到人物脸”这类共享路径句，分别写摄影机、焦点、手指和叶片的实际状态。
- 因果主线只约束观众应当读懂的事件与关系变化，不规定拍法、景别、表演术语或直投句式；不做复杂度评分、固定节点数量、因果关键词门禁或永久角色缓存。原文故意保留真相时，只设计人物当下相信什么和观众应保留的疑问，不把推断升级为事实。
- 不生成含创意决策的前置 `scene_contract.json`。最小事实连续性台账、因果主线、表演弧和节奏诊断只保留在审片报告，不成为正式 Markdown 字段；不从成稿反向恢复创意合同，不逐镜运行创意正则，不用重复字段证明同一事实。
- 技能目录不保留旧创意正则、合同恢复、逐镜修复器或其兼容入口。若外部旧文档提到这些工具，视为已废弃，不能恢复到主流程。

## 交付硬事实

原样保留人物身份、事件顺序、因果和全部台词/OS/OV/系统音；默认按当前 Seedance 兼容基线执行每镜 `>0s` 且 `<=15s`，活动界面确认其他真实单镜上限时，以该上限替换并在交付报告记录依据。不得设置直投提示建议字数或硬性字符上限；只有当前平台界面已确认真实输入上限时才执行该限制。`both` 默认共享镜号、时长和 `台词` 原文；只有目标界面差异有证据且审片证明需要时才允许时长分歧。正式目录不得引用 `staging/` 资产，未审核线稿不得进入正式目录或 Seedance 参考位。

### 交付命名与全局视觉基线补充

- 正式 Markdown 文件名固定为 `第{集数}集_总时长{分镜总时长}秒_即梦Seedance分镜.md`。集数取源文或用户指定值并使用两位数字补零；分镜总时长为本集所有正式镜头时长之和，四舍五入到整数秒，且必须与正文 `项目信息` 中的数值一致。若源文没有集数且任务不是明确单集，先获得集数；明确单集测试使用 `第01集`。
- 在正式 Markdown 增加 `## 全局视觉基线`，写出本集跨镜复用的物理光源方向、主辅光关系、综合色彩、色卡材质落点、白平衡、对比度、黑位、高光、背景亮度和肤色基准。它是可执行的创意指导，不得写内部编号、审片分数或“非投喂”说明；逐镜 `视觉控制` 仍必须独立写出当前可见结果，不得用“沿用全局”省略。
- 默认上限可由交付校验的 `--max-shot-duration <已确认秒数>` 覆盖；没有平台证据时不要凭历史经验改变默认值，也不要把该参数用于限制提示词字符数。
- `both` 只有在审片报告记录目标界面差异证据后才可向交付校验追加 `--allow-target-duration-drift`；该开关只允许时长不同，不允许镜号、台词、人物、空间、道具或稳定终态漂移。

修改技能后运行系统 `quick_validate.py`，并用未见过的完整剧本前向测试；成功标准是成片设计质量、语义清晰、声音可执行、审核有效和无循环修补，不是创意正则通过率。
