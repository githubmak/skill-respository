# 即梦剧情表演分镜

## 输入

唯一硬必填是可完整读取的源文本或源文件。导出目录、视觉风格、画幅、`seedance_target`、创作档位和视觉复核档位均可选；
缺失时按 [task-adaptation-contract.md](references/task-adaptation-contract.md) 补足。目标固定为即梦平台及其
Seedance 视频模型，不生成其他平台版本。`seedance_target` 可写 `auto`、`2.0`、`2.5` 或 `both`。创作档位可写 `fast`、`balanced` 或
`director`，默认 `balanced`；视觉复核档位可写 `auto`、`required` 或 `off`，默认 `auto`。这些是任务内部参数，不改变现有脚本命令接口。

创作档位含义：`fast` 只生成一套创意方向并做设计层复核；`balanced` 生成两套明显不同的创意方向后选一套；
`director` 生成三套方向、建立导演审美合同并对关键镜头做更严格的比较。`auto` 视觉复核在有本地关键帧/视频时运行，
无视觉文件时只运行设计审美复核并标记 `visual_review=NOT_RUN`；`required` 在缺少视觉文件时阻塞交付；`off` 只关闭真实画面复核，
不得关闭设计审美复核、源文闸门或工程校验。

脚本在 Windows 与 macOS 执行同一合同：Windows 使用
`powershell -ExecutionPolicy Bypass -File scripts/run_skill_tool.ps1 <script.py> <args...>`，macOS 使用
`python3 <script.py> <args...>`；不得因平台差异跳过源文闸门、shadow report 或双版本一致性校验。

除源文缺失/不可读，或歧义会改变人物身份、剧情事实和关键动作因果外，不阻塞式追问。纯打斗/武器动作、九宫格、剧本改写、合规审核和纯配音任务不进入本流程，也不调用其他本地技能替代。

## 引用路由

任何任务先运行 `scripts/route_task.py <generate|audit|video-review>`。生成任务附 `--source <源文路径>`；
只读取返回的 `read_first`，再按源文命中的 `read_on_demand` 读取专项规则。`run_only` 中的脚本直接运行，
不预读源码。常规低风险生成只读：

1. [runtime-core.md](references/runtime-core.md)：完整流程的最小运行核心、源文边界和不可降级项。
2. [output-template.md](references/output-template.md)：唯一输出结构和字段顺序。

`task-adaptation-contract.md`、`runtime-brief.md` 和 `generation-risk-guards.md` 仍是维护与专项诊断的权威展开版；
不要在常规任务中与运行核心重复加载。路由只减少上下文读取，不删除剧情分析、创意方案、导演审美合同、拆镜、表演、
连续性、制作控制、验证或导出步骤。

只在触发时追加一个或少量专项引用：

- 非默认剧情类型：喜剧、悬疑、亲密关系、画外威胁、无台词因果、时间压缩蒙太奇或非战斗行动，读 [narrative-mode-routing.md](references/narrative-mode-routing.md)。
- 对白/表演：情绪弱、节拍平、关键反应或口型交接复杂，读 [prompt-performance-rules.md](references/prompt-performance-rules.md)；主要人物表演风格漂移时再读 [performance-baseline-library.md](references/performance-baseline-library.md)。
- 视觉质感：画面塑料、平、廉价，或用户要求构图、焦段、材质、胶片感，读 [visual-attraction-rules.md](references/visual-attraction-rules.md)；需要类型化色卡案例再读 [color-palette-library.md](references/color-palette-library.md)；明确需要环绕、多莉变焦、闯入式镜头、时间错位或日漫式切空再读 [cinematic-grammar-library.md](references/cinematic-grammar-library.md)。
- 场景预设：常见现代场景缺少可用锚点时读 [scene-preset-library.md](references/scene-preset-library.md)；陌生题材直接从源文建空间，不加载预设。
- 空间机位：多人轴线、柜台/桌/车/门口、跨文件同地复现或正反打风险，读 [spatial-camera-continuity.md](references/spatial-camera-continuity.md)。
- 物理结构：躺/坐/抱/扶/摔/起身、道具/衣物转移、门车门、手机/UI、人群或窄空间移动，读 [physical-structure-continuity.md](references/physical-structure-continuity.md)。
- 拍法参考：需要现成调度模式或同类镜头反复失败时，读 [shot-patterns.md](references/shot-patterns.md)，不得原样套用。
- 维护与复核：修改技能时读 [regression-cases.md](references/regression-cases.md)；校验通过后仍有复杂物理/空间歧义时读 [validation-checklist.md](references/validation-checklist.md)。

同一规则只按最窄触发加载。不要因为“想提高质量”同时读取全部视觉、空间和表演库。

## 执行

1. 通读完整源文，只冻结不可改变的事实合同：人物身份、台词/OS/OV/系统音、事件顺序与因果、场景、道具归属、起始状态、终态和跨场关键状态线；不要在此阶段过早冻结构图、焦段或运镜。
2. 按创作档位生成 1-3 套明显不同的场景方案。每套只写内部创意卡：戏剧命题、观众立场、唯一新认知、信息控制、视觉母题、构图/镜头语法、表演策略、光影材质、声音策略、场景记忆点和主动拒绝的俗套。方案必须改变观看立场或戏剧机制，不能只是替换色彩形容词；不改源文事实。
3. 匿名比较创意方案并选定一套，不做平均化拼接。比较第一焦点、构图必要性、情绪可见性、视觉记忆点、镜头运动收益、生成可行性和连续性风险；将选定结果冻结为内部导演审美合同。导演审美合同只保留 1 个场景主命题、每个连续五镜窗口的 1 个必选与第 2 个候选记忆锚点、构图家族、运镜触发规则、表演基线、光影材质基线、禁止套路和允许变化槽位，不输出到最终投喂字段。
4. 以导演审美合同为上层约束，按观众认知拆镜头组；每组只完成一个新认知，并分配铺垫、升压、峰值、释放或缓冲。为每组指定景别、角度、一个构图骨架、主次焦点和一个固定理由或单一路径；同场连续三组不得重复完整组合，除非明确是情绪冻结。按同场子镜头的实际顺序检查每个滚动五镜窗口：必须安排至少 1 个、目标 2 个记忆锚点；锚点优先落在转折、揭示、权力变化、决定性动作或情绪余波，第 2 个锚点必须与第 1 个在观众位置、信息揭示、权力关系、视觉载体中至少两项不同。其余镜头负责铺垫、承接和留白，不与锚点争夺强度，但每镜仍必须有一个源文专属、不可替换的导演选择。
5. 为每个子镜头先写内部“创意内核”：本镜新认知、情绪变化、第一视觉焦点、关系变化、最小表演泄露、运镜必要性、结束画面，以及它是否为记忆锚点。再按创作档位生成镜头级微方案：`fast` 1 个，`balanced` 2 个，`director` 3 个；候选必须改变观众站位、信息出现顺序、人物关系几何、遮挡/显露或声画触发中的至少一项，不能只是替换焦段、颜色、形容词和推移距离。匿名选择后做“可替换性测试”：去掉人名、地点和关键道具后若仍能原样用于无关剧情，判为平庸并重做。每镜选定一个源文专属导演选择；锚点另写可见载体、成立原因和关系/认知变化。再建立不输出的结构化镜头事实合同。合同逐人记录 `物理槽位/画面侧/身体面向目标/摄影机可见面/视线目标`，逐镜记录 `摄影机所在侧/拍摄方向/关系轴侧/构图焦点/运镜族与落点/时段/主光源与受光面/道具持有人与支撑/终态`。`【画面描述｜直接复制】` 和 `【本镜制作控制】` 必须从同一合同分别编译，禁止先写两段自然语言再凭关键词对齐。每个子镜头只承担唯一任务、一个主动作或一条简单路径；人物镜补充表演策略与泄露点，有现实动力源时补充一条因果动态链。每条直接提示词还要独立复写时段、门窗/屋外亮度、承担主光的物理光源、受光结果和曝光终态；相邻镜头切换景别、焦段、人物数量或门窗构图时，仍要复写同一时段和同一主光源，不能依赖模型跨镜记忆。高风险任务过载时先拆镜。只有锚点镜在 `【本镜制作控制】` 的 `画面质感` 行末追加 `记忆锚点：<可见主体与关系事实>；成立原因：<为何必须这样构图/遮挡/调度>；关系/认知变化：<由何状态变为何状态>`；直接提示词只自然写入对应的可见事实，不复制“记忆锚点、成立原因、关系/认知变化、观众看清”等制作元语言。
6. 应用生成风险闸门，再按当前事实写可独立投喂的正向提示词。每生成一个子镜头，先写入临时场景草稿并运行
   `scripts/incremental_validate.py <scene_draft.md> --current-shot <Sx-xx-x>`。按返回的 `repair_scope` 修复：
   `field` 只改点名字段，`shot` 只改当前镜，`pair` 只改点名镜头对，`window` 只改点名三镜或五镜窗口；
   每一级最多局部修复两次，仍失败才升级一级，不默认重写整场。增量脚本只读，不直接修改主 Markdown。
7. 严格使用当前输出模板；多场景默认分文件，共用冻结的全局事实索引和已选导演审美合同。`auto` 生成一份双兼容 Markdown；
   `2.0`/`2.5` 生成对应优化版；`both` 从同一份事实合同导出
   `*_Seedance2.0.md`、`*_Seedance2.5.md` 和非投喂的 `00_双版本索引.md`。
8. 保存后仍必须按上述平台入口运行
   `scripts/validate_storyboard.py --shadow-report --seedance-target <目标> <output.md>`；`both` 一次传入
   两份主文件（索引可选），修复全部硬错误后交付。
9. 工程校验通过后，必须进行设计审美复核：先逐镜执行可替换性测试并检查第一视觉焦点、构图必要性、情绪是否可见、源文专属导演选择是否真的进入直接提示词、镜头是否模板化、运镜是否改变关系或认知、质感是否来自光源/材质事实；任一镜只剩通用景别、固定/微推、通用微表情和停稳时直接 `REVISE`。再逐个滚动五镜窗口核对记忆锚点密度。对每个已标锚点先遮住 `记忆锚点/成立原因/关系或认知变化` 自述，盲描述实际提示词会形成的画面，再判断能否用一个具体画面句复述、是否依赖源文关系、是否区别于相邻镜头、去掉它是否损失信息或情绪。仅换焦段、颜色、形容词、微推距离、空泛氛围或无因奇观的标记不计数；两个锚点若只做同一种构图变化，也只计 1 个。复核只允许输出 `PASS` 或 `REVISE` 及最小 `repair_scope`，不得用追加“电影感/高级感”等形容词代替修复。先盲描述当前设计，再对照创意内核，避免模型顺着自己的理由确认。
10. 若任务提供本地关键帧或视频，在设计审美复核后追加真实画面复核：用 FFmpeg/FFprobe 抽取首帧、关键动作帧和尾帧，由 GPT-5.6 视觉能力检查构图、焦点、质感、情绪、遮挡、人物关系、运动收益和终态；对已标记忆锚点额外检查第一眼是否命中预定主体、构图关系是否真实成立、情绪是否可见、能否与相邻镜明显区分。视觉失败的锚点从窗口计数中移除并回修该五镜窗口，不能用设计层 `PASS` 抵消。`scripts/review_video.py` 只负责客观技术指标，不能代替视觉审片。无视觉文件时记录 `visual_review=NOT_RUN`，不得伪造实际画面通过；`required` 模式下直接阻塞交付。
11. 设计或视觉复核失败时，按 `field -> shot -> pair -> window -> scene` 的最小范围回修并重新运行完整工程校验；每一级最多局部修复两次。只有事实合同、空间锁、人物身份或连续状态出现广泛级联错误时才重写受影响场景。复核报告和修复日志不进入即梦提示词。
12. 全部复核通过后可运行 `scripts/concise_storyboard.py <output.md>` 生成 `.concise.md` 快速阅读版；主 Markdown 不变，投喂与验证仍以主文件为准。

## 硬约束

- 原样保留所有台词、OS、OV、系统音、内心独白及其标点；可见台词进入直接提示词并驱动正确口型。每条 OS 必须在 `【画面描述｜直接复制】` 和 `【表演与声音】` 中显式写成 `人物名OS：“原文”`，人物名必须与本集角色声音锁定表一致；禁止裸写 `OS：“原文”`、用“他/她/角色”代替姓名，或只靠上下文推断说话者。OS/OV/系统音进入直接提示词但画内人物闭口并有可见反应。
- 每个子镜头 `<=15s`；`【画面描述｜直接复制】` `<=500` 中文字符，不设最低字数。是否合格只看当前镜头类型的必要语义是否完整；短而完整的物件、空景、蒙太奇和无台词因果镜不得为凑字数增加人物、动作、光效或重复事实。
- `both` 两份文件必须镜号、时长、台词/OS/OV/系统音原文、人物、空间锚点、道具归属和终态对齐；只允许改变
  Seedance 适配层的光影精度与动态复杂度措辞。共享镜头仍采用15秒以内的跨版本安全时长。
- 每个直接画面描述必须写出本镜具体构图骨架、主次焦点和固定/单一路径镜头策略；同场连续镜头不能只换台词而复用同一景别、角度、构图和运镜组合。
- 每个直接画面描述开头必须写明确时段和承担主光的物理光源，末尾写背景亮度、主光方向、色温或曝光保持到结束；门外、屋外、窗外、门框或窗框进入画面时必须写外部亮度与天空黑位/天光状态。同场相邻镜头的时段和主光源必须一致，除非源文明示时间流逝、次日、闪回或可见光源切换。
- 人物位置、身体面向、摄影机所在侧、拍摄方向和可见面必须互相闭合：同一人物不得同时面向并背对同一空间/人物，不得背对摄影机却写正面可见；门槛镜必须逐人写门内/门外侧，摄影机在门外朝屋内拍摄时，同侧人物若面向屋内人物，摄影机只能看到其背面或侧背，不能写正面可见。
- 创意方案必须先于正式镜头锁定；最终只交付被选方案对应的一套事实合同，不能把多套方案混写成安全但无观点的平均结果。
- 每场必须有一个明确的视觉主命题；同场任意连续 5 个子镜头的滚动窗口至少有 1 个、目标 2 个可描述的记忆锚点。少于 5 镜的场景不为凑配额虚构锚点，但仍可在真实转折处设置。锚点必须来自人物关系、道具、空间、光影或声音的可见因果事实，并在现有 `画面质感` 行声明可见载体、成立原因和关系/认知变化；不得靠无源霓虹、强雾、强颗粒、泛光、复杂运镜或自称“高级/震撼/亮眼”制造。硬校验保证每五镜至少一处设计锚点，实际成片是否成立只由真实画面视觉复核确认。
- 每个关键镜头必须能回答“观众先看什么、为什么看这里、看完关系或认知改变了什么”；若不能回答，优先改构图、景别、遮挡、表演或剪辑承接，不得只增加提示词形容词。
- 每个非关键镜头也必须有一个源文专属导演选择，能回答“这一镜为何不能由普通中近景对白或通用反应镜替代”。选择可落在观众位置、信息顺序、人物距离/遮挡、道具用途、空间边界、声音触发或动作后果，但每镜只选一个主机制。安静、固定和留白可以成立，前提是静止本身改变压力、期待或关系；若删去人名、地点和关键道具后仍适用于无关剧情，必须重做。
- 连续镜不得机械复用“固定机位 + 0.2米微推 + 微表情后停住”。运镜必须由进门、注视交接、接应、情绪压力或空间揭示触发，并写起幅稳定、唯一主路径、动作承接和落幅；没有可见收益时改为有构图目的的固定镜或拆成关系镜/反应镜。
- 每个人物镜必须把最后20%的终端稳定事实写进正文：可见人数和槽位固定，人物边界与脸/手/腿分开，道具归属和支撑不变，摄影机减速停稳，光线曝光不跳变，不进入新人物、不产生重复人物并保持到结束；不得只靠负面提示词处理重影或重叠。
- 每个子镜头包含五个基础字段；可选字段只在真实降低风险时添加，不输出空字段。关键帧字段必须成对出现。
- 最终 Markdown 必须包含 `## 制作质量总控`，每个子镜头必须包含 `【本镜制作控制】`；画面质感、光效与曝光、动态美学、表演与情绪、穿帮控制、抽卡策略、蒙太奇与剪辑必须转成可读执行信息，不能只留在内部分析或校验器中。
- `【本镜制作控制】` 不得成为第二套事实：其中每项可见执行结果必须与 `【画面描述｜直接复制】` 共享同一具名主体、焦点对象、光源与受光面、运镜族与落点、表演动作、道具/支撑和可见人数；风险等级、自动检查、失败后拆镜、后期与复核决定只留在制作控制。只出现同类关键词而人物或对象不同仍判失败。
- 直接提示词必须写视觉场景前缀、当前可见主体、空间/物件关系、构图骨架与主次焦点、景别机位、固定或单一路径、表演/声音、动机光影或剧情材质、可见变化或明确保持、最后20%终端锁定。人物镜必须写身体面向和由剧情触发的可见表演泄露；纯物件/空景镜改写物件朝向、构图焦点、环境因果和声画衔接，不机械补人物朝向。
- 双人对峙、相见、肩后和正背关系必须拆开四个事实：摄影机位于谁的哪一侧并朝哪里拍、每人身体/胸口/脚尖实际面向谁、摄影机看到每人的正面/背面/侧面、每人视线落向谁。`正面可见` 不等于 `面向镜头`；关系镜禁止用 `两人对望/面对面` 代替双方相反朝向，也禁止把所有人写成面向镜头。
- 两名及以上具名人物入画时，逐人写带坐标基准的物理槽位和身体面向；关系镜再逐人写摄影机可见面与视线目标，并写摄影机物理位置、拍摄方向及保持在人物关系轴同一侧。相邻镜头人物屏幕侧不得无因翻转；确需越轴时必须连续拍出中性机位和屏幕方向交换过程。
- 源文明示 POV、对镜口播或打破第四面墙时，允许双人关系中唯一一人直视镜头：正文必须点名人物、授权类型、时间窗、身体仍面向对手或可见转向过程，以及视线回到对手/保持直视到落幅的结束状态；其他人物继续看向场内目标。普通正反打的正脸可见不属于此例外。
- 世界方位和 `前景/后景/画面占比` 只作辅助。门口镜必须逐人绑定门槛内/外侧，摄影机方向与真实背景相容；回家/进门写成 `门外起点 -> 跨过门槛 -> 屋内终点`。具名前后景人物同时入画时，正文必须写允许遮挡的身体部位以及必须保持可见的脸、手、关键道具或视觉通道。
- 多人纵深按共同支撑面、近大远小和真实相对身高建模；儿童不得仅靠画面百分比控制大小，必须锁定头顶相对成人肩/胸位置、头身骨架和脚底接地。同类道具同时入画时以持有人加形状、颜色或内容物区分，不能只写 `双篓/双篮`。
- 成对关键帧不是简写区。每个首帧、关键帧和尾帧必须复写本镜时段、主光源、可见人数、具名人物槽位/面向/可见面/视线、摄影机位置/方向/关系轴侧、关键道具归属与支撑；与直接提示词任一事实冲突或省略时验证失败。
- 下一镜开头重写上一镜结束后的当前可见事实；不依赖即梦跨镜记忆，不在直接提示词写 `上一镜、继承、延续、尾帧、切到、反打到、后期插入`。
- 交付复核不能只看闪烁、曝光和清晰度，必须核对动作方向、门槛两侧、人物面向与视线、比例/遮挡、构图主次、光源连续、伪文字和声音轨道；技术指标通过而语义失败时仍判不合格。
- 清晰入画人物必须有主表演、受击/观察反应或低幅活体状态；无反应容量者降为肩线、弱虚化或画外。
- 光影适配：2.0 使用简洁动机光、浅至中等阴影和清晰面部受光；auto 使用主要受光面清晰、背光侧
  有层次的中等阴影；2.5 可增加动机光层次、局部有来源的环境色、稳定黑位与高光滚降。三者都禁止
  无来源的正面均匀补光。原有固定句“脸部受光均匀、鼻侧/眼窝/下颌只保留浅阴影”只作为2.0适配，
  不再作为所有目标的唯一光影默认。
- 道具、衣物、朝向、人体支撑、门车门、手机/UI和空间穿越发生变化时，写清起点、接触/支撑、可见转换和稳定终态；一镜不承担三项以上高风险任务。
- 光影必须落到现实或剧情可解释的光源、方向、接收面、阴影/高光结果或剧情材质；动态光只允许一次有因变化并写稳定落幅。环境色不得覆盖脸和活动手，体积光不得遮挡五官。
- 任何负向具体视觉概念先改写成目标身份、服装、地点和道具事实；操作型手机固定屏幕朝使用者、镜头只见背面或斜侧边缘。
- 不用机械校验句补字段；缺失项必须改写成真实画面事实。
- 设计审美复核和真实画面复核是独立状态：`design_review=PASS|REVISE`，`visual_review=PASS|REVISE|NOT_RUN`；`NOT_RUN` 不等于通过。审美评分只作证据，不能替代事实合同和硬校验。
- GPT-5.6 视觉复核采用“盲观察 -> 意图对照 -> 最小修复”三步；视觉模型不得只复述提示词或把自己的生成理由当作画面证据。每次复核必须指出实际焦点、关系变化、情绪证据和失败镜头范围。
- 创作自由集中在导演审美合同和允许变化槽位；人物身份、台词、事件因果、空间连续性、道具归属、口型和终态仍是不可变硬事实。关键镜头允许大胆构图，但不能以牺牲硬事实换取风格。
- 增量校验是前置门禁，不替代最终完整校验。最终校验发现局部错误时仍按 `field -> shot -> pair -> window -> scene`
  的最小范围升级；只有空间锁、人物身份、源文覆盖或连续状态发生广泛级联错误时才重写受影响场景。
