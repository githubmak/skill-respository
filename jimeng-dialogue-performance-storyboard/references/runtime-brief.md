# 维护与故障诊断扩展

常规生成不读取本文件；唯一运行权威是 `runtime-core.md`。本文件只在维护、回归失败或成片诊断时定位缺失层，不重复生成流程，也不得降低创意、审美、运镜、表演、空间或门禁要求。

## 诊断入口

- 合同文件出现重复字段、结果与编辑内容不符：运行 `scene_contract.py <contract> --strict-completeness --compact --report <reports>/contract.json`；重复键直接阻断，不接受“最后一个值覆盖前面的值”。
- 终态或门槛词反复触发误判：先运行 `scripts/prompt_preflight.py <draft.md> --advisory --compact --report <reports>/prompt.json` 定位负向边界句和过早终态词，完稿后再用严格模式复验；该工具只报风险，不替导演改写正文。
- 双人关系线稿出现同向箭头：关系镜默认 `facing_mode=mutual`；有意看向道具、门外或第三目标时显式声明 `facing_mode=independent`，避免把语义例外藏在省略字段里。
- 工程通过但提示词变得通用：运行 `scripts/creative_preflight.py <draft.md> --advisory --compact --report <reports>/creative.json`，检查第一焦点、源文专属关系/因果、光影职责、摄影机服务和结束余像；严格结果失败时回导演选型，不继续堆制作控制。
- 设计审查通过但没有关键帧/视频：manifest 的 `delivery_status` 必须是 `PROVISIONAL`，不能作为最终审美交付。

- 风格误配、画面塑料或题材同质化：检查证据路由后读取 `visual-direction-profiles.md`；单个风格词不得触发强 profile。
- 人物、衣物或环境呆滞且缺少可解释动力源：读取 `liveness-motion-grammar.md`；把动静角色、主体触发与相位差编译进直接提示词和制作控制，不增加模板字段。
- 人物站位、面向、机位、边界或正反打失败：先用 `spatial-camera-runtime.md` 与 `blocking-facing-reference.md` 修同源 SVG/PNG 和事实合同；只有复杂桌边、纵深、人群或重复失败才读取 `spatial-camera-continuity.md`，最后修提示词。
- 支撑、接触、道具/衣物转移、门车门、UI或人群失败：读取 `physical-structure-continuity.md` 与命中的 `generation-risk-guards.md`。
- 普通对白单薄、潜台词/人物专属性在提示词中丢失、口型错配或听者失活：先检查 `performance_ir -> 受保护可见载荷 -> 直接提示词 -> 回译` 哪一段失真，再读取 `prompt-performance-rules.md`；人物基线漂移才读 `performance-baseline-library.md`。
- 构图、焦点、光影或运镜收益不足：读取 `visual-attraction-rules.md`；只有确需复杂路径时再读 `cinematic-grammar-library.md`。

## 四系统定位

| 系统 | 最小事实底图 | 失败信号 | 首选修复 |
|---|---|---|---|
| 空间 | `空间ID/锚点/实体遮挡/边界两侧与通道/人物槽位/身体面向/可见面/视线/摄影机位置与方向/轴线侧` | 换位、越轴、门内外颠倒、应见人物不在视锥 | 回修同组 JSON 并重导 SVG/PNG；正反打复用 `blocking_id`，只换单机位 |
| 状态 | `start_boundary -> 唯一可见转换或保持 -> end_boundary -> 下一镜当前事实` | 道具跳手、支撑跳变、无过程转身或穿越 | 补接触/支撑/跨越中间态；过载则拆准备、转换、终态 |
| 镜头 | `第一焦点/构图骨架/景别焦段/机位/固定理由或单一路径/关系差值/稳定落幅` | 构图可删、机械微推、运动只放大、连续镜同构 | 保留胜出关系几何，重设计摄影机响应或改为有目的固定镜 |
| 表演声音 | `行为签名演变/表演候选胜者/目标/策略/身体倾向/泄露/选择代价/反应传播/唯一口型` | 通用微表情、无因大动作、全员同时反应、运镜遮掉演法 | 回到候选赛换表演机制；再让景别与摄影机服务胜者，压低非主人物 |

四系统分别诊断、共同闭合：心理标签不能代替状态，空间坐标不能代替摄影机可见性，制作控制不能补写直接提示词不存在的画面，工程通过不能覆盖设计或视觉失败。

## 复杂度与修复范围

- `轻量`：单一主体任务，无高风险转换；仍须满足完整画面、表演、光影、运镜和终态质量。
- `标准`：多人关系、简单道具或普通正反打；只增加一个真实需要的可选功能。
- `高风险`：三人以上清晰入画、复杂支撑/转移/UI/边界穿越/强运镜；最多三个可选功能，超出即拆镜。
- 可选功能只用于降低已命中风险：空间与道具锁、镜头执行、口型分窗、镜内状态转换、剪辑衔接、正向约束、坏相负面、成对关键帧。不得为空字段或同义复述付费。
- 先保留不可降级视觉核心，再减少动作、运动、时长或字段负担。完整修复与复验规则以 `review-pipeline.md` 和确定性脚本为准。
