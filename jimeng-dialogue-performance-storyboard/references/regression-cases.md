# 回归测试样例库

本文件用于修改技能后做回归验证，不参与常规生成。每次大改后至少用其中 3 类样例生成短分镜并跑 `scripts/validate_storyboard.py`；涉及对应风险时优先选该类样例。

macOS 修改源文闸门后运行 `python3 scripts/test_source_gate.py`；修改输出校验器后先运行
`python3 scripts/test_validate_storyboard.py`，再运行 `python3 scripts/validate_storyboard.py --shadow-report <output.md>`。
Windows 使用 `powershell -ExecutionPolicy Bypass -File scripts/run_skill_tool.ps1 <script.py> <args...>` 执行相同脚本和参数；
两端不得省略完整分镜校验。

## 固定样例类型

1. 普通双人对白：双人面对，无道具转移，无 UI；验证轻量镜头不缩水，台词进画面描述，听者有低幅反应。
2. 三人警局多人戏：民警、主角、旁观者/混混；验证可见人数、柜台内外侧、口型唯一、背景弱化。
3. 手机消息文字：手机背面或屏幕不可见但消息需要可读；默认验证直接提示词只预留安全区、具体文字进入后期文字句。另设用户明确要求 AI 画内生成的短气泡样例，验证文字不超过12字、允许文字近似、二维浮层、安全区、不贴手机和不跟随透视。
4. 吊椅/沙发姿态：人物靠坐、蜷腿、后续翻身或坐起；验证人体支撑点跨镜承接。
5. 道具递交：银行卡/手机/杯子从A到B；验证起点、接触、握住、松手、新持有人稳定。
6. 正反打：A肩后拍B，再B肩后拍A；验证保轴、肩线比例、双方身体面对、距离/道具复写。
7. 商业街轻喜剧：并行走、误会、停顿反应；验证暖色街景不抢脸、路人弱化、轻喜剧张弛。
8. 情绪峰值余波：拒绝/承认/质问后被击中者停住；验证独立余波镜、关系定格、不新增道具变化。
9. 负向概念泄漏：在住宅女性镜头中故意写 `不要护士帽/不是医院`；验证失败样例被拦截，改成目标发型、服装和客厅锚点后通过。
10. 手机游戏操作：人物双手横持手机玩游戏；验证缺少屏幕用户侧/镜头侧朝向时被拦截，补齐 `屏幕朝向本人 + 手机背面或斜侧边缘朝镜头` 后通过；直接提示词、必要约束、补充负面、关键帧和即梦视频提示任一字段出现 `游戏界面露出/HUD/按钮/技能栏/血条/小地图` 都必须失败，负面字段改用 `手机翻面、屏幕乱字、手机高度跳变、手机漂浮穿手、手指畸形、握持穿模`。
11. 彩色环境光与肤色：蓝灰/暗绿环境光落入人物脸部；验证没有正向中性肤色锚点时被拦截，补齐脸部受光均匀和浅阴影落点后通过。
12. 多人纵深与人物比例：两名具名人物分处前后景；验证只有 `A在前景、B在后景` 时被拦截，补齐到镜头距离、同一连续地面、近大远小的投影尺度和稳定头身比例后通过。环境自身的前景/后景层次不得误报。
13. 门外看屋内的正背关系：A在门外前景背对摄影机并面向B，B固定在门槛内侧面向A且正面可见；验证此写法通过，`A背对镜头、B正面对镜头`、双方同向或只写 `两人对望` 被拦截。
14. 回家与门槛穿越：门外起点、一脚跨槛中间态、双脚进入屋内终态；验证缺少任一阶段、常驻屋内人物跑到门外、摄影机在门外却把门外夜色写成背景时失败。
15. 前景儿童遮挡后景成人：儿童头顶低于成人肩线，脚底共地，真实头身稳定；前景只遮住成人下半身，成人脸/手/支撑物从视觉通道可见。只有百分比或只有 `前景/后景` 时失败。
16. 同类道具辨识：两只篮/篓分别绑定持有人，并以圆口鱼篓与方口菜篮、颜色或内容物区分；只写 `双篓归属固定` 时失败。
17. 授权直面镜头：源文明示打破第四面墙，双人关系中仅A在限定时间直视镜头，B继续看A，A落幅回看B或保持直视；验证通过。无授权、多人一起看镜头、缺少时间窗/结束状态或把普通正反打写成直视镜头时失败。
13. 词面与镜头语义碰撞：环境水纹不得自动判为空镜，人物躲在他人肩后不得判为过肩镜头，人物摇头和眼神移动不得判为摇镜或移镜；对应的零人水纹特写、摄影机位于人物肩后、镜头推近仍须正常触发。
14. 悬疑证据揭示：人物发现门锁划痕后确认有人进入；验证先限制信息、再给痕迹、后确认事实，不在建立镜提前展示入侵者或答案。
15. 无台词视觉因果：人物发现漏水、寻找来源并关闭阀门；验证原因、动作、环境反馈和新状态可见，不用旁白替代画面。
16. 亲密关系试探：两人共享雨伞，一人迟疑后调整伞面；验证距离和手部变化来自源文，不用粉色滤镜、无依据慢动作或强行触碰代替关系。
17. 时间压缩蒙太奇：同一工作台连续数日完成一件器物；验证固定锚点、每镜一个状态增量、光线/时间变化和最终成果，不写成一镜自动变形。
18. 非战斗行动：人物沿走廊搜寻出口、遇到封路后改道并抵达楼梯口；验证目标、路线、障碍、调整和到达状态连续，不跳过中间路径。
19. 镜头类型与长度建议：准备一条低于建议区间但语义完整的无台词因果镜，以及一条位于建议区间或更长、但缺少结束状态/动作因果的冗长镜头；验证前者语义通过且显示 `length_guidance=short`，后者语义失败并显示 `semantic-incomplete/despite-length`；不存在最低字数硬错误。
20. 类型建议区间：分别准备对白、多人关系、无台词因果、空镜/物件插入、蒙太奇、非战斗行动、道具转移和未分类镜头；验证分类稳定，只有道具/姿态/UI/门车门等转换进入高风险状态转换，环境水纹、人物摇头和人物躲在肩后不因词面碰撞误分类。
21. 古风游戏自动适配：制作要求写“古风游戏”时启用东方空间、自然色、材质分层、动机光与动作重量；同一句只出现在角色台词中时不得触发，最终直接提示词不得保留游戏名称。
22. 现代剧场景生命：住宅、办公室、咖啡馆或夜车对白中，验证光源有现实来源，主体动作与环境/材质响应存在因果和差速，落幅保留一项低幅余波；不得连续重复慢推、眨眼、薄雾或窗帘轻摆。
23. 动态光影：门开、车灯经过、云影变化、手机熄屏或烛火受风只触发一次局部光影变化；验证光线方向、受光面、肤色与黑位连续，体积光和综合色不覆盖脸、嘴和活动手。
24. Seedance 双目标：同一份事实合同导出 `*_Seedance2.0.md`、`*_Seedance2.5.md` 与 `00_双版本索引.md`；两版镜号、时长、台词和道具状态一致，光影适配词有目标差异且索引不可投喂。
24. 全局比例与条件支撑：全局正向锁定必须包含骨骼/头身比例、真实身高体型、四肢长度、地平线/消失关系、两人身高差和物理距离投影规则，并区分站立、行走、坐卧与腾空支撑；通用负面只保留无因尺度跳变、无因浮空、透视、穿模和肢体风险，四类支撑负面只在对应动作镜追加。
25. 语义级去套路：同组连续三镜分别写“缓慢推近、轻推、小幅推进”，验证归入同一 `camera_push` 家族并产生影子诊断；只有两镜命中或三镜分别使用稳定机位、道具接触和现实光源变化时不报。
26. 动静曲线与相位：古风开门侧风、现代车灯掠过、杯子落桌三类场景均先锁静止锚点，再按主体触发、第一响应、延迟响应、余波稳定编译；复杂对白、道具转移、坐卧/腾空镜只保留一个低幅响应。
27. 多证据题材路由：分别准备宫廷关系戏、江湖追踪、仙侠施法、现代住宅对白、都市夜车和乡村家庭场景；每例至少用三个独立证据通道确定基础 profile，并只叠加一个剧情 modifier。单个“古装/夜景/乡村/悬疑”词或台词中的风格词不得独立触发。
28. 风格冲突与回退：古代宫廷不得自动加入江湖动作，现代夜景无店招/车流证据不得加霓虹，乡村不得自动暖黄怀旧，悬疑不得自动染绿，唯美不得自动加雾/辉光/慢动作；证据矛盾或低置信时回到通用电影化默认。
29. 前置源文闸门：空文件/不可读文件必须阻断；缺少场景标题、人物表、视觉细节或只有散文段落只产生 advisory，仍允许建立保守空间锁并进入分镜流程；风险词只路由专项 reference，不直接变成画面事实。
30. OS 说话人绑定：在直接提示词、表演与声音、口型分窗中分别放入裸 `OS：“我没事。”`、代词 `她OS：“我没事。”` 和声音锁定表外的 `陌生人OS：“我没事。”`，验证三者失败；改为声音锁定表内的 `沈星雨OS：“我没事。”` 后通过。OV、系统音、内心独白和旁白不套用人物名 OS 规则。
31. 夜景跨镜光照连续：第一镜写夜晚小院、油灯主光，第二镜切换焦段、门框构图和可见人数但省略时段/门外亮度，验证失败；第二镜复写 `同一夜晚、门外深蓝黑位、油灯仍为主光源、曝光保持` 后通过。若第二镜改成白天日光且没有时间流逝依据，必须产生相邻镜时段和主光源冲突。
32. 门槛人物面向与机位闭环：摄影机在门外朝屋内，A与摄影机同在门外并身体面向屋内B时，A写背面/侧背可见通过，写正面可见失败；同一人物同时面向门外和背对屋外、背对摄影机又正脸可见失败。摄影机在屋内朝屋外时，不得把屋内写成后景。

## 最小通过标准

- 每个样例至少 1 个镜头组、2-4 个子镜头，组总时长等于子镜头和。
- 全局锁定含空间索引、制作级色卡、角色声音锁定表。
- 每条直接提示词含压缩视觉前缀、景别机位、人物面向、光影/材质、台词/声音文本、结束状态。
- 高风险样例必须出现对应防护字段：可见人数、状态转换、口型分窗、必要约束、补充负面或关键帧。
- 触发人体支撑变化、道具/衣物转移、UI文字、门车门/电梯空间穿越、复杂正反打或强运镜时，必须通过关键帧触发检测：要么添加成对关键帧字段，要么拆成更简单的准备/转换/终态镜头。
- 直接提示词、必要约束和单镜负面不得用否定的职业/制服/地点实体排除错误结果；原台词中的同类词不计入视觉概念泄漏。
- 操作型手机必须锁定屏幕朝使用者、手机背面或斜侧边缘朝镜头，并在 `【状态继承】` 复写手机朝向；没有展示任务时不得写可读游戏 UI。
- 普通镜头直接提示词优先收敛在 200-320 字；单镜视觉前缀只写一次、场景锚点最多 2 个、光影/材质执行 1 个、视觉增强 1 个、结束状态 1 次。普通镜头最多 1 项可选功能，高风险镜头最多 3 项，成对关键帧按 1 项计数。
- 可见人物脸部同时遇到彩色环境词或体积光词时，必须有正向肤色锚点和阴影落点；不能只写“不发青/不发灰”。
- 具名人物分处不同纵深时，必须同时锁定人物距离/层级、连续地面或承载空间、近处较大与远处较小的画面投影，以及稳定头身比例/骨架/真实身高关系；肩后局部遮挡按肩线占比单独判断。
- 非默认剧情模式必须内部明确主模式、至多一个副模式、观众已知/角色已知差、暂不揭示、本组唯一新认知、可见信息载体和余波；不得把模式标签、导演术语或内部模式卡输出到最终 Markdown。
- 悬疑不得提前泄露答案，喜剧不得用夸张表情提前泄梗，亲密关系不得用滤镜代替距离变化，无台词镜头必须有可见因果，蒙太奇每个片段只推进一个状态增量，非战斗行动必须保路线和到达状态。
- 影子报告必须为每个子镜头输出且不改变 `OK/FAIL`：类型建议区间只用于校准，不设最低字数硬门槛；重点记录短而完整和长而不完整的镜头，不为消除 `SHADOW` 提示机械补字。
- 校验脚本返回 OK；若失败，优先修生成规则，不给样例硬补丁。
