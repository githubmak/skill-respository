# 强制审查流程

工程校验只证明文件可交付，不能证明镜头好看、表演准确或 Seedance 不会误解。设计审片必须由大模型完成；有线稿、关键帧或视频时还必须查看真实画面。审查记录与 manifest 均为非投喂文件。

## 1. 设计审片

审片者同时阅读完整源文、场景导演方案、全部直投提示和相邻镜。优先使用未参与生成的新上下文；不可用时明确记为 `self_check`，不要伪称独立审查。第一遍先不依赖内部因果笔记，只从源文和最终直投提示判断观众实际能读到什么，第二遍再与导演方案对照，避免用创作者本意替画面证明。

先从最终直投提示反向还原 `触发 -> 人物当下的理解或目标 -> 关系策略与可见行动 -> 对方接收和反应 -> 新的关系、信息或身体状态`，再判断它是否准确表达原文。原文故意保留真相时，不强行补全答案，只检查人物当下认知和观众应保留的疑问。重点检查：

- 原文事实、关系转折、信息顺序和全部声音是否完整，时长是否给表演与停顿留下现实空间。
- 因果链是否通过可见动作、表演、反应时机和信息释放成立，而不是只存在于场景说明或创作者意图中；无法还原时先定位断在原文理解、触发、策略、听者接收还是新状态。
- 人物行为是否来自此刻目标与压力，听者反应是否有正确时机，动作、口型和道具是否能实际执行。
- 空间、身体面向、视线、遮挡、边界、支撑与道具归属是否闭合；所有多人镜是否至少能唯一还原具名人物槽位、躯干朝向、视线目标和画面左右，空间风险镜再核对双脚、头部朝向、摄影机轴侧和当前可见面，而不是停在“面对”或无参照的左右；逐对比较上一镜稳定尾态与下一镜物理起态，人物位置、躯干/头部朝向、视线目标、站坐支撑、活动手、持物人与接触关系、门窗或边界若改变，是否有可见转换或明确时间省略；前镜尾帧的持物若在后镜手部或画面内仍可见，后镜是否明确持有人、手别和承载/接触关系，若不再可见，前镜或切点是否交代放下、交接、出画或时间省略；仅由换机位造成的正侧背可见面变化是否被正确识别为画面投影，而没有误写成人物转身。
- 摄影机与剪辑是否帮助观众读取表演、关系或信息；静止和运动是否都是有意识的选择，而非模板或风险退化。
- 每场 `VC-Sn` 是否完整锁定物理光源、方向、强弱、色彩与材质落点、白平衡、曝光层级和肤色；逐镜视觉控制是否能独立生成且与基线一致。逐对比较相邻镜的光源数量/方向、冷暖归属、背景亮度、黑位、高光、肤色和主色落点；变化是否有明确物理触发、影响范围与新稳定态。
- Seedance 文句是否清楚区分摄影机、焦点、人物/手部和道具，是否明确先后、参照系、容器归属与稳定终态；没有可见场景依据时是否误用南北方位，焦点是否同时声明多个互斥主体。
- 画面是否有题材和人物专属性，强弱节奏是否合适，是否留下值得保留的结束画面。

这些是判断问题的视角，不是逐镜关键词清单。反向还原是大模型的语义审片，不得改造成脚本评分、关键词命中、固定节点数量或新的交付字段。简洁镜头、静止镜头、克制表演和有意悬念不因缺少某种术语而失败；只有它们未实现当前场景意图时才判 `REVISE`。审片者写出具体画面问题、依据和受影响镜头，不给关键词补丁。因果可还原、连续性闭合、直投提示可独立理解且工程事实通过后停止，不为增加分析量继续展开因果笔记或生成第二套方案。

## 2. 真实画面审片

- 空间 SVG/PNG：先核对具名人物、站位、面向、机位、视锥、遮挡、边界和标签可读性。几何正确后还要由视觉能力查看实际 PNG；双 PASS 后才可提升到 `approved-jimeng-2d/`，其中 PNG 可作为即梦空间关系参考，但仍不是成片美术参考。
- PyVista/VTK 人偶：执行模型直接查看渲染报告列出的每个 `camera_index` 的 `mode=audit` 与 `mode=clean` 图片，不能把 JSON、文件尺寸或非空像素检查当成视觉审片。核对身份色、姓名、站坐、身体/头部朝向、视线、左右手接触、锚点高度、边界开口、摄影机和视锥；摄影机有 `path`，或同一镜号有 `physical_phase=start|end` 时，必须成对查看起点和终点，并确认改变项和保持项与直投文字一致。再查看同一物理状态同一 `camera_index` 的干净图，核对实际机位中的人物数量、前后层次、遮挡、可见面、支撑、接触和构图。净图必须来自该摄影机的 VTK 透视相机，不是通用俯视观察角；多机位缺少 `camera_index` 时阻断。图片固定为 1920×1080、16:9，投喂图固定为 `镜头号_即梦_3D_空间关系.jpg`；摄影机路径或人物物理首尾使用 `_start` 与 `_end` 配对，审核图再加 `_审核`，例如 `S1-08_即梦_3D_空间关系.jpg`、`S1-10_即梦_3D_空间关系_start.jpg`。状态与机位索引保留在审核报告，不写入投喂文件名。未双 PASS 的图片留在 `staging/mannequin/`，不得写入正式 Markdown；人偶只约束空间与动作身份，不提供角色外貌、服装、材质、光影或成片风格。
- 关键帧：查看人物身份和数量、构图、景别、表演、光影、影调、色卡、比例、支撑、道具和文字。只有与导演方案一致的图才可作为 Seedance 参考。
- 视频：查看首帧、关键动作帧和尾帧，并检查动作先后、口型、反应传播、摄影机路径、转焦、光影漂移、肤色、背景稳定和结束保持。`review_video.py` 的客观指标不能代替视觉观看。

纯文本交付没有图片或视频证据时记录 `visual_review=NOT_APPLICABLE`，设计审片 PASS 后可以 FINAL。存在任何交付视觉资产时必须查看真实画面并记录 `PASS|REVISE`；`NOT_RUN` 只能保持 PROVISIONAL，不能标记 FINAL。

## 3. 修订

先判断失败属于原文理解、因果断点、拆镜/容量、表演、空间、摄影机、焦点、动作预算、光影色卡、平台措辞或素材本身，再由模型重做对应决定。因果断点只展开受影响的一段，不重建全场分析；优先只重做受影响镜头及直接连续性，但不要为了缩小 diff 保留错误结构。

同一问题连续两轮仍只是增加限定词、重复终态或移动字段，停止局部补丁，回到拆镜、机位、动作顺序或信息释放重新设计。脚本不生成修复文案，也不限制模型应选择哪种创意方案。

真实生成失败时，先定位第一个使素材不可用的层级：身份与人数、空间与左右、动作与接触、摄影机路径、表演与口型、焦点与景深、光影与材质。下一次生成只改变一个最可能主因并保留可比较条件；这是模型用于判断因果的测试方式，不是脚本循环，也不要求按固定顺序创作。

参考冲突先修素材；动作无法完成先检查准备态、路径与拆镜；遮挡后重建先检查遮挡前后身份状态；焦点跳动先检查观看中心和转焦终点；曝光或材质闪烁先检查真实光源、高亮动态和细碎纹理。需要完整问题族与停止条件时按需读取 [seedance-generation-diagnostics.md](seedance-generation-diagnostics.md)。

## 4. 提升与最终状态

所有视觉资产先放在 `staging/`。二维空间图通过审核后使用 `promote_blocking_reference.py record` 与 `promote` 提升到 `approved-jimeng-2d/`，PNG 可作为即梦空间关系参考；人偶图逐机位完成 audit/clean 双审后使用 `promote_mannequin_reference.py record` 与 `promote`，只把干净图提升为空间/机位/姿态/接触参考。未通过或哈希变化的文件不得进入正式层。关键帧与视频也必须记录用途和真实画面 PASS 后再被 Markdown 引用。

使用 `review_manifest.py create` 创建 review attestation，声明设计/视觉结论并绑定源文、主输出和正式资产 SHA-256。它不证明审查质量、审查者身份或独立性。无需单独执行 verify；最后运行 `validate_delivery.py --final --review-manifest <manifest>` 直接复核哈希。设计 PASS，且视觉 PASS 或确无视觉证据时为 NOT_APPLICABLE，才能标记 FINAL。
