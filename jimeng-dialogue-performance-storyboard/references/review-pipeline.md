# 强制审查流程

工程校验只证明文件可交付，不能证明镜头好看、表演准确或 Seedance 不会误解。设计审片必须由大模型完成；有线稿、关键帧或视频时还必须查看真实画面。审查记录与 manifest 均为非投喂文件。

## 1. 设计审片

审片者同时阅读完整源文、场景导演方案、全部直投提示和相邻镜。优先使用未参与生成的新上下文；不可用时明确记为 `self_check`，不要伪称独立审查。

先复述这一场真正要让观众理解和感受什么，再判断当前方案是否做到了。重点检查：

- 原文事实、关系转折、信息顺序和全部声音是否完整，时长是否给表演与停顿留下现实空间。
- 人物行为是否来自此刻目标与压力，听者反应是否有正确时机，动作、口型和道具是否能实际执行。
- 空间、身体面向、视线、遮挡、边界、支撑与道具归属是否闭合；逐对比较上一镜稳定尾态与下一镜物理起态，人物位置、躯干朝向、站坐支撑、活动手、持物人与接触关系、门窗或边界若改变，是否有可见转换或明确时间省略；前镜尾帧的持物若在后镜手部或画面内仍可见，后镜是否明确持有人、手别和承载/接触关系，若不再可见，前镜或切点是否交代放下、交接、出画或时间省略；仅由换机位造成的正侧背可见面变化是否被正确识别为画面投影，而没有误写成人物转身。
- 摄影机与剪辑是否帮助观众读取表演、关系或信息；静止和运动是否都是有意识的选择，而非模板或风险退化。
- 每镜独立色卡、影调与光影是否足以单独生成，主辅点缀色是否有可见落点，亮暗/饱和度/肤色是否明确，真实光源、方向、受光面、阴影和材质响应是否协调并服务剧情，镜间是否无因漂移。
- Seedance 文句是否清楚区分摄影机、焦点、人物/手部和道具，是否明确先后、参照系、容器归属与稳定终态；没有可见场景依据时是否误用南北方位，焦点是否同时声明多个互斥主体。
- 画面是否有题材和人物专属性，强弱节奏是否合适，是否留下值得保留的结束画面。

这些是判断问题的视角，不是逐镜关键词清单。简洁镜头、静止镜头或克制表演不因缺少某种术语而失败；只有它们未实现当前场景意图时才判 `REVISE`。审片者写出具体画面问题、依据和受影响镜头，不给关键词补丁。

## 2. 真实画面审片

- 空间 SVG/PNG：先核对具名人物、站位、面向、机位、视锥、遮挡、边界和标签可读性。几何正确后还要由视觉能力查看实际 PNG；双 PASS 后才可提升为工程参考。它仍不是成片美术参考。
- 关键帧：查看人物身份和数量、构图、景别、表演、光影、影调、色卡、比例、支撑、道具和文字。只有与导演方案一致的图才可作为 Seedance 参考。
- 视频：查看首帧、关键动作帧和尾帧，并检查动作先后、口型、反应传播、摄影机路径、转焦、光影漂移、肤色、背景稳定和结束保持。`review_video.py` 的客观指标不能代替视觉观看。

`visual_review=auto` 在存在视觉文件时执行；`required` 在缺少或未通过时阻塞；`off` 只能在用户明确不要视觉审片时使用，并把交付保持为 `PROVISIONAL`，不能标记 `FINAL`。

## 3. 修订

先判断失败属于原文理解、拆镜/容量、表演、空间、摄影机、焦点、动作预算、光影色卡、平台措辞或素材本身，再由模型重做对应决定。优先只重做受影响镜头及直接连续性，但不要为了缩小 diff 保留错误结构。

同一问题连续两轮仍只是增加限定词、重复终态或移动字段，停止局部补丁，回到拆镜、机位、动作顺序或信息释放重新设计。脚本不生成修复文案，也不限制模型应选择哪种创意方案。

真实生成失败时，先定位第一个使素材不可用的层级：身份与人数、空间与左右、动作与接触、摄影机路径、表演与口型、焦点与景深、光影与材质。下一次生成只改变一个最可能主因并保留可比较条件；这是模型用于判断因果的测试方式，不是脚本循环，也不要求按固定顺序创作。

参考冲突先修素材；动作无法完成先检查准备态、路径与拆镜；遮挡后重建先检查遮挡前后身份状态；焦点跳动先检查观看中心和转焦终点；曝光或材质闪烁先检查真实光源、高亮动态和细碎纹理。需要完整问题族与停止条件时按需读取 [seedance-generation-diagnostics.md](seedance-generation-diagnostics.md)。

## 4. 提升与最终状态

所有视觉资产先放在 `staging/`。空间图通过审核后使用 `promote_blocking_reference.py record` 记录结论，再用 `promote` 提升；未通过或哈希变化的文件不得进入正式层。关键帧与视频也必须记录用途和真实画面 PASS 后再被 Markdown 引用。

使用 `review_manifest.py create` 绑定源文、主输出和正式资产的 SHA-256，再用 `review_manifest.py verify` 验证。任何字节变化都使旧结论失效。最后运行 `validate_delivery.py --final --review-manifest <manifest>`；设计与视觉均 PASS、哈希有效且正式目录无 staging 引用时才标记 `FINAL`。
