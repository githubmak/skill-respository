# Camera Analysis — 单镜头摄影与画面精修

本技能只处理一个明确镜头的摄影、动作可见性和画面问题。用户可以要求“让这个镜头更有压迫感”“把中景改成 POV 是否成立”“为这个动作设计运镜”“修正越轴和景别跳级”“规划前中后景与光影”或强化术法、粒子、VFX、机甲活动等关键动作。用户未指定目标运镜时，先比较适配候选，再直接采用最优方案；不暂停等待确认。所有任务都交付完整摄影精修结果，不以候选分析或简版建议替代成稿。它不输出整场导演稿，不重写完整对白或无关表演段落。

## 与 jingxiu-fenjing 的分工

- camera-analysis：单镜头、单一主变化、一个明确摄影目标；同时负责画面空间、构图、光影、人物/道具可见状态和必要的连续性修正。
- jingxiu-fenjing：完整分镜或整场生成单元；统筹整剧节奏、镜头组、表演、动作、光影材质、声音和时长，并按原生成单元模板交付。
- 原 `frames-analysis` 的单镜画面分析职责已并入本技能；不再调用或创建独立的 frames-analysis。
- 若用户同时给出完整生成单元，只提取目标镜头及其必要前后信息；不要把单镜摄影任务扩成整单元重写。

## 打斗、术法、粒子与机甲能力（内置单镜模式）

当本镜包含攻击、格挡、闪避、追击、反制、术法、法阵、法器、能量攻击、爆炸、冲击、机甲活动或武器接触时，先在本镜范围内补足动作与特效因果，再进入摄影方案。此能力独立维护于本技能，不调用 `fight-scene-video`，也不把单镜任务扩成整场战斗。

### 本镜动作因果

写清主体、目标、起势、路径、接触或规避、受力/反作用、结果和停止状态。允许补足动作准备、连接、错峰反应、环境反馈和不改变结果的收势；不得新增攻击轮次、能力功能、伤势、胜负或剧情结果。整场攻防顺序未知时，只设计当前镜头能够成立的动作节点，并标记需要由前后镜承接的状态。

### 本镜战术与多人职责

先判断本镜动作服务的威胁、目标和控制权变化，再选择观看距离和摄影重点。主攻防保持一个第一读点；同框其他人物只承担本镜确有依据的护人、避让、警戒、承重、确认伤势或介入准备，并按感知和空间错峰。不得用连续固定中景、镜头晃动或特效亮度代替攻击路径、规避、接触和结果。

### 本镜术法与 VFX

识别术法当前阶段：来源、聚能、成形、施放、运行、接触、命中/被挡/偏转、余波或消散。特效必须写清源点、形态、传播方向、第一作用、人物和环境反馈、遮挡关系及退出边界；粒子按核心、结构、流动、命中和残留层组织，不让特效遮住本镜主读点、关键接触或人物面部。

### 机甲与大型动作

本镜出现机甲或大型主体时，补足支撑、重心、关节启动、武器挂载、接触路径、受力和局部环境响应。景别、焦段和运镜必须能让观众读到重量或动作结果，不以抖动、爆炸亮度或慢动作代替物理证据。

### 本镜生成降级

当人物、动作、术法和粒子无法在同一读取窗口成立时，优先保留主体、路径、接触/规避和结果；再通过前景遮挡、降低粒子层级、缩小运动范围、明确切点或拆分相邻镜头降级。不得用随机抖动、无因爆炸、慢动作或满屏光效替代动作因果。

### 用户术法视觉输入

用户可以在调用时指定本镜术法的颜色、能量材质、粒子形态、运动规律、命中反馈、残留方式和禁止表现。用户指定优先于本技能默认规则；与冻结剧情、能力或结果冲突时保留事实并说明冲突，不静默改写。

### 打斗与术法示例库（按需读取）

涉及术法、粒子、斗法、VFX或机甲活动时，读取[单镜打斗与术法示例库](references/single-shot-fight-vfx-examples.md)。示例用于检查本镜可见证据、材质反馈、时间节拍和景别承载，不是固定模板；用户术法视觉输入、全局影调和前后镜状态优先。

## 画面、构图与光影职责

本技能同时完成原 `frames-analysis` 的单镜画面分析，不再拆分到另一个 skill。先锁定“观众第一眼必须看见什么”，再组织前景、中景、背景、人物、道具、光影和摄影机：

- 前景：遮挡、框景、景深和叙事功能；中景：主体、动作和关系；背景：地点、时代锚点、纵深和氛围。
- 构图：主体画面左/中/右、负空间方向、视线余量、遮挡关系、水平线和纵深，不使用空泛的“高级构图”。
- 局部光影：可针对本镜设计主光方向、软硬、冷暖、明暗反差、轮廓/环境光、遮挡和材质响应；可提出符合场景逻辑的摄影光源安排。不得改变已经确立的时间、天气、实体光源事实、全局影调或角色/场景资产；若新增的是剧情内可见光源，必须有剧本依据或明确标为建议，不得默认为既成事实。
- 人物与道具：明确位置、身体状态、面向、视线、持物和接触状态，保持与前镜的可见连续。
- 色彩：选择一个主色调和必要的辅助点缀，按当前场景需要决定面积，不套固定比例；全剧色卡由 `color-palette-tone-design` 负责。

### 多人同框空间闭环审核

当观察者与被观察对象同时入镜，或镜头包含多人前后景、目送/注视、接近/离开、前景框景、升降/后撤/弧移等高风险关系时，必须执行同镜空间闭环审核；普通单人镜头只做必要的空间检查，不机械增加字段。

审核时必须在同一空间假设下核对：

- 人物前后顺序、画面左/右位置和纵深关系；
- 每个人的躯干朝向、头眼朝向，以及摄影机实际看到的正面、侧面或背面；
- 被观察对象相对观察者的位置，视线是否真的能到达对象；
- 摄影机相对关系轴所在侧、起始机位、运动路径和终止机位；
- 摄影机运动前后是否无说明地换到关系轴另一侧，或造成左右位置、人物朝向和远近尺度突变。

审核结论必须能够回答：“摄影机站在哪里、每个人面向哪里、对象位于谁的哪一侧、镜头能看到每个人的哪一面、镜头停在哪里。”不得只用“目送、看向、肩部轮廓、侧后方、前景框景”等语义代替空间关系。人物要求远离摄影机并在画面中变小时，运动方向必须实际远离镜头。

空间审核发现问题时，先调整人物站位、身体/头眼朝向、前后景关系和摄影机相对位置，再检查运动路径是否需要保持在关系轴同侧。用户已锁定的景别、焦段、时长或运镜不得被静默改写；当前空间仍无法成立时，说明冲突并给出最小替代方案。

### 超大巨物的尺度呈现（按需启用）

当本镜的剧情或资产明确设定超大生物、人物、器物或建筑，或用户指出“看起来不够大”时，主动检查观众能否从画面读出其**世界尺寸**，而不只看到它占满画框。已锁定的真实尺寸与相对比例保持不变；未给出尺寸时不擅自编造米数。

- 选择场景中尺寸可信的参照物，使它与巨物处于相近纵深、共享地面或明确的接触面，并能同时看见足底、根部、基座、投影或受力结果。只靠“巨大”字样、低机位、广角或近大远小，不能代替同平面比例证据；不得把参照物缩成微缩模型，或把它推远伪造体量。
- 检查画框是否反而削弱巨型感：若高大背景完全压过主体、巨物被轻松完整装进宽阔风景且缺少参照，可在本镜任务允许时改用局部越框、正常尺度物旁的接触、由下至上的连续揭示，或保留参照物的较紧全景。选其中能服务本镜主变化的一种，不把脚到头仰摇、震地音效或裁切当作固定套路。
- 巨物运动要与体量相称：交代支撑、重心、接触路径及环境的局部响应，并让摄影机的高度、距离、焦段和运动速度保持可执行。环境反馈以实际材质和受力为准，不凭空增加地震、建筑损毁或慢动作；局部镜仍须在可见处保留尺度线索，跨镜不得忽大忽小。
- 把观众必须看见的比例证据写入现有“指向性目标、空间分层、景别与构图、连续性检查”栏目，并在终幅复核参照物是否仍可读。若单镜时长或既有约束无法同时容纳动作与尺度证据，在完整结果中说明取舍或最小拆镜方案，不擅自重编整场。

详细光色、材质和光型词库仅在当前镜头确有需要时读取 `references/lighting-color-encyclopedia.md`、`references/color-mood-atlas.md` 或 `references/lighting-pattern-library.md`。

## 运镜选择与自动采用

### 模式 A：用户已指定目标运镜

用户明确写出具体运镜或摄影机制，例如“改成极速穿越”“使用人物 POV”“做半环绕”“改为推拉变焦”，即视为已经确认。直接检查其是否符合剧情、空间、画幅、动作和生成稳定性：成立则进入精修；不成立则先说明冲突，并给出最接近原目标的降级方案，不悄悄换成另一种机制。

### 模式 B：用户未指定目标运镜

分析镜头的主变化、信息揭示、人物动作、观看关系、空间路径、时长、画幅和起落幅；内部比较 2—3 个非同构候选，按叙事收益、空间可达性、动作/口型可读性、时长匹配和生成稳定性选出最优方案。候选必须由镜头的实际触发产生，不能只按情绪标签匹配；高级不等于复杂，固定凝视、受限 POV 或短促焦点交接可以胜过复合运镜。直接采用首选并在完整结果的“采用方案”中说明选择依据；不输出单独候选清单，不请求用户确认。

### 最终修改范围

- 输入是完整“### 生成单元”时，沿用原标题、字段、台词和约束，只修改目标镜头所影响的摄影与构图、时间线、起落幅及特殊正负约束；无关内容逐字保留。
- 输入只是单镜头描述时，按下方单镜头摄影精修合同交付。
- 若最优方案需要增加时长、拆分遮挡接缝或改变相邻镜头接点，在完整结果中说明实际影响；只调整目标镜头及必要接点，不扩写整场或改动剧情事实。

## 单镜头交付精度

### 时长与节拍

- 选择方案时内部估算候选的最低可执行时长；最终完整稿说明采用时长及其节拍安排，不能把需要蓄势、运动、减速和停留的机制塞进不足的时段。
- 修改阶段把镜长拆成可结算阶段：触发/蓄势、主运动、减速或焦点交接、稳定终幅。各阶段首尾连续，合计必须等于该镜头或所在生成单元分配给它的时长。
- 同时发生的摄影、人物动作、口型和声音按并行结算；先后发生的切换与结果停留才累加。急推、快摇、极速穿越等也必须保留能够读取终幅的停止时间。
- 用户未提供时长时给出建议范围和采用值；用户锁定时长时只设计能在该时长内完整执行的方案，不能靠省略触发或停幅强行套用。

### 画面构成

- 明确主体在画左/中/右及画面占比，并按实际需要写前景遮挡、中景行动、背景空间、负空间方向和视线余量；“有层次、电影感、构图高级”不算构图说明。
- 景别、焦段、机位距离与动作可见性必须一致。特写只承载脸部、手部、接触或证据等局部信息；需要读取路线、全身受力或多人关系时必须给足画面尺度。
- 每个连续时间窗只有一个第一读点、一个主运动和至多一次主焦点交接。运动开始前写现实触发，运动中写可达路径，结束时写停止条件和稳定终幅。
- 需要变焦、遮挡接缝、隐藏剪辑、速度变化或虚拟摄影机时，必须明确它是实拍位移、镜头转向、光学变焦、剪辑接缝还是后期时间效果，不能混成“镜头快速变化”。

### 摄影语言

- 固定=机位不移动；横移=机位沿横向轨道移动；推/拉=机位前后位移；摇/俯仰=机位位置基本不变而镜头转向；环绕=围绕主体改变方位；变焦=焦距变化。禁止“固定机位横移”“固定镜头推进”等自相矛盾表达。
- 使用“具体主体/对象—触发—摄影机路径—焦点行为—停止—终幅”的执行句。避免“高级、唯美、震撼、电影感、氛围拉满”等不能量化或生成的空泛结论。
- 多人镜头和跨句描述使用人物姓名或明确角色名；只有指向唯一时才使用人称代词。方向必须以画面左/右、主体前/后、机位相对方位或空间锚点表达，不能只写“往那边、继续向前”。
- 数值只在提高可执行性时使用，并与时长、路径和场地相容；不伪造无法从输入建立的精确三维坐标。空间基准不足时写相对坐标和待建立项，不把猜测写成事实。

## 单镜头决策顺序

1. 确定本镜唯一主变化、打斗/术法动作节点（如有）和观众必须新看见的证据。
2. 若涉及打斗、术法、粒子、VFX或机甲活动，先完成本镜动作因果、术法阶段、粒子层级、命中/规避、环境反馈和生成降级判断；不扩写整场。
3. 检查用户是否已指定目标运镜；未指定则内部比较候选并直接采用最优方案。
4. 确定主体、观看关系和终止状态，再选景别、角度、焦段和构图。
5. 只保留一个主运动（或有职责的固定镜头）和至多一次主焦点交接。
6. 把触发、路径、幅度/速度、停止条件和终幅写成可执行描述。
7. 用前镜检查轴线、屏幕方向、景别梯度、焦段跳变、光位连续、术法/VFX连续和机位空间跳跃；多人同框或前后景关系触发时，完成同镜空间闭环审核；必要时给出最小缓冲方案。

普通固定、推拉、横移、跟拍或环绕已足以交付目标时，不调用经典运镜候选库。只有普通方案不足以表达观看顺序、空间关系、动作重量或高辨识摄影机制时，才读取 [经典运镜候选库](references/classic-camera-movement-candidates.md) 比较候选。候选只迁移摄影机制，不在最终提示词写片名、导演名或致敬标签；不成立时采用条目降级方案。

## 量化门槛

- 9:16竖屏优先使用纵向推拉、仰俯、脚到脸揭示和小幅中轴弧移；大幅横向移动、宽横移和大环绕必须有明确场地与叙事理由。
- 16:9横屏可使用横移、跟拍、推拉、弧移和较完整的空间调度，但仍只保留一个主运动。
- 不使用固定速度、半径、角速度或曝光阈值；只有动作、场地或连续性确实需要时，才给出近似的自然速度或简单距离。
- 焦段服务于景别和空间关系：只在能提高可执行性时给广角/标准/中长焦及近似 mm，不把精确焦段当作硬门槛。
- 同场对话默认保持180度轴线；越轴必须写人物移动、机位绕行、遮挡或缓冲空镜的可见过渡。
- 景别梯度使用“大远景 → 远景 → 全景 → 中全景 → 中景 → 中近景 → 近景 → 特写 → 大特写”；跳级可以成立，但必须写信息、证据、冲击或主观转折动机。
- 固定镜头必须承担等待、观察、压迫、对峙或结果停留；不可仅因降低生成风险而默认固定中景。

多人同框或前后景关系触发时，内部完成空间闭环：核对机位相对位置、人物左右/纵深与身体/头眼朝向、视线对象、可见正侧背面、轴线侧、运动路径和终止点。该审核不作为单独栏目输出；只把影响生成的空间信息写进“空间分层与画面”“连续性检查”等正式字段。输出前复核时间、景别/焦段、主体位置、运动方向、轴线、焦点、停止条件、终幅、光影依据和声音来源。

区分内部审核与最终提示词：内部可用有依据的近/中/远关系、地标和必要的估算检查可达性；最终提示词优先使用空间锚点和可见关系，不写 XYZ 坐标、精确米/厘米位移、EV、色温 K、角速度或曝光工程值。焦段、景别、时长及有助生成理解的自然语言速度可以保留；不得把无法从输入得到的精确数值写成事实。

## 光位责任

本技能可以设计本镜完整的局部光影，包括方向、软硬、冷暖、反差、强弱、轮廓/环境光和材质响应，并检查与前后镜及全局影调的连续。设计须服从场景、时间、天气和资产事实；摄影布光可作为画面方案提出，剧情内实体光源不得无依据地新增为既成事实。全剧色卡和全局影调由 `color-palette-tone-design` 或项目既有规范负责，本技能不得擅自重设。

## 独立使用

1. 读取本镜任务、主体动作、画幅和必要前镜信息。
2. 缺前镜参数时标注“首镜/无前后对照”，不编造连续性结论。
3. 先写主变化和证据；用户已指定目标运镜则评估并落实，未指定则内部比较 2—3 个候选、选出最优方案并直接完成精修。
4. 始终交付完整输出合同；在“采用方案”中简述首选及其理由，不停在候选阶段等待确认。
5. 用户明确要求经典机制、名场面摄影或高辨识运镜时，按需读取候选库并比较普通方案与高级候选。
6. 只交付一个完整的最终采用方案；如风险过高，在完整稿的“风险与降级”中说明替代方案，不输出整场分镜或多套平行成稿。

## Structured JSON 兼容

收到显式兼容 dispatch packet 时，必须使用 packet 指定的数据包规则：根对象为 {"items": [...]}，每项包含 id、shot_id 和 subshot_id，并写入 _batch_output_path；禁止写公共 output_path。普通用户调用仍使用上方 Markdown 合同。
