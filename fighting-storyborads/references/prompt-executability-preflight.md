# 提示词可执行性预检

在镜头答案已确定、编译最终 Markdown 之前读取；单生成单元和连续战斗均可使用。本预检只处理生成模型可能误解或同时无法完成的描述，不重新选择剧情、招式、胜负、主视觉机制或已成立的摄影目的。无法从静态文本确定的风险标为待成片验证，不伪称已失败。

## 常见可观察冲突

- **互斥姿态与动作**：同一时间要求角色稳住身体说话、被击飞、双手结印和持剑接触，或在未松脱前再次挥动被卡住的武器。先保留剧情要求的动作和接触结果，按物理先后改写；必要时拆镜。
- **竞争主读点**：同一窗口让人物微表情、全身武器路线、巨物显形、关键命中和远处环境破坏同时清楚可见。按观众必须依次辨认的事实分配起幅、运动、终幅或相邻镜，不靠“全部清晰”解决。
- **身份与空间漂移**：复杂遮挡、快速切视角、多人同形服装、道具换手、无地标跃迁或 VFX 遮住起终态。保留可辨身份、归属、方向和落点的最少锚点；已成功的表演与大效果不因风险猜测被一律删除。
- **重复或相互矛盾的指令**：定位同一时空内的互斥姿态、不可达路径、状态冲突、重复占时或相互抵消的正负命令。多个动作中心、主效、精细轨迹或逐秒安排可以成立，不单凭数量与详细程度判失败；保留采用的具体设计和表现力，删除真实重复与误伤原设定的限制。
- **多个单元合投的时间冲突**：多个 G 单元各从 `0.0秒` 起算，文件合计时长却大于一次生成预算，或同一事件在摄影、特效和时间线重复占时。先核对实际投喂范围与目标时长，明确连续顺序和接点；必要时拆成独立生成段或重配非锁定时间，不让模型自行压缩攻防与结果。
- **主动作被约束淹没**：必须发生的突袭、闪避、接触与受力埋在长段的机位、面部、色彩和负面条件之后。保留必要空间锚点，把动作链与峰值放到本镜前部；摄影与特效只补各自独有的信息，不逐栏复写同一事件。不能为了精简删除已确认的主效规模或剧情结果。

## 最小修复顺序

1. 复述必须生成的事实：谁在何处、用什么、对谁、接触或规避、结果与下一接点。确认没有遗漏原文明确事实。
2. 指出**同一观看窗口**的具体冲突及其可见后果。不要把复杂、华丽或虚拟运镜本身当作失败证据。
3. 优先调整语义顺序、主次、遮挡、焦点和起终状态；其次合并无观看收益的重复或有具体互斥证据的冗余；审美、风格、速度、压迫和感官刺激也是有效收益，不按是否推进剧情删掉装饰与动作；若关键任务仍互斥，再拆成相邻镜或自然接缝处的生成段。
4. 反向检查修复前后的角色身份、动作性质、能力规则、台词、控制权和结局一致；高能镜的规模证据与特效层级未被修成泛光。
5. 按正常观看速度想象成片：观众已认出攻击意图后，下一可见变化是否是距离、攻线、对手选择或实际接触；决定性打击是否能在无特效时仍看到身体反作用；峰值是否比装饰拖尾更醒目。三者有一项不成立，退回动作与节奏设计，不靠格式通过宣称完成。

预检结果只用于修改正文，不新增“风险等级”“模型参数”“审计结论”等交付字段。成片已有失败证据时，改用 [生成反馈诊断](generation-feedback-loop.md) 找最早错误并做增量修复。结构和时长仍由对应模式的固定合同及校验脚本验证；本预检不能代替实际生成测试。
