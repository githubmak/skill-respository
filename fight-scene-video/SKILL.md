# 打斗与斗法分镜

把明确剧情视为边界，在未定义的攻防过程内进行动作导演、摄影、VFX 与声音设计。目标是让战术、人物情绪、空间受力和视听规模一起推动战局。真人实拍仅作创意预演；实际拍摄由合格动作指导和现场安全团队执行。

## 先选输入模式

- **已有剧情的连续战斗**：用户要求设计一段完整战斗或连续攻防时使用；输入可为剧本、场景或多组连续动作，即使包含法天象地或精彩单镜也不改走单单元。保留已明确的攻击、规避、接触、顺序、伤势、控制权、能力与装备规则、人物性格及结局。若原文只有“激战、苦战、反击、获胜”等概述，可设计具体试探、攻防、调整和直接反应，使人物从既定起态抵达既定结果。读取[整场层次与题材](references/battle-arc-genre.md)。
- **原创连续战斗**：输入仅有题材、交战双方或目标。先以用户事实为先建立最低必要的目标、能力及代价、场地、初始关系和结局；空白可设计，不无因扩写身世、宗门或后续故事。建立后按连续战斗执行，并在 `剧本推断补全` 标明本次原创设定和依据。读取[整场层次与题材](references/battle-arc-genre.md)。
- **单镜或单生成单元玄幻设计**：用户明确只要一个镜头、一个关键片段，或输入已有 `### 生成单元 G…` 时使用；即使提供了完整战斗作为上下文，也只设计指定范围。没有单元标题时，按输入建立必要的 G 编号、承载镜号和自然时长；不凭此补写整场。读取[单生成单元导演与交付](references/single-unit-delivery.md)；其中的结构、时间线和默认 35 秒上限专属于此模式。

三种模式均不得把“更刺激”解释成改写已明确的事件、能力功能、重大伤势、台词或胜负。已写明的动作可补准备、连接、受力、反作用、收势和余波；新增动作只放在未定义过程内。用户指定的风格优先。

## 配乐开关

默认关闭：仍设计剧情需要的台词、配音和动作/环境音效，不主动新增背景音乐。用户明确要求“配乐、BGM、背景音乐、纯音乐、欢快/激昂旋律”等时开启；仅要求配音或音效不触发。已有稿件中的配乐即使本轮未开启也应保留，除非用户要求删除或修改。

开启后先从人物处境、控制权、动作节奏、场面尺度和台词/命中位置确定**整场音乐情绪弧**，再把每段转成可用于选曲或音乐生成的自然语言：情绪类型、旋律性格、节奏快慢、**主奏乐器与伴奏/节奏乐器各自的作用**、开始/变化/收束时机，以及需给台词或关键音效让位的地方。电子、环境或无传统乐器的配乐改写主导音色与节奏音色及其作用，不能只写“氛围感”。用户指定曲风、乐器或已有音乐优先；未指定时只做有剧情依据的选择。配乐可欢快、紧张、激昂、恢宏、悲壮或静默，不默认“打斗必燃”。不把每拳每剑机械打点，不写无依据的百分比、逐字口型帧或混音频段参数；汗水滑落等无可听声源的画面细节不写成音效。声效仍须有来源、距离和先后，配乐不得掩住原台词与决定性接触。

整场音乐不能只定情绪：从攻防目标、控制权变化和结局提炼一条可辨的主题短句或音型，写明主奏音区/奏法、和声或持续音、节奏层各自承担什么，以及主题在蓄势、攻防转折、主峰与结果中怎样变奏。每镜配乐子项至少交代实际乐器/音色、旋律或节奏做法、画面触发、为台词或决定性音效退让的声部、恢复点；静默镜写停奏原因和再次进入。只有“激昂、恢宏、渐强、鼓点加密”而没有这些可听动作，须重写声音部分。配乐开启时人声保持清楚的干声，音乐、环境和音效不加处理性混响、回声或拖尾来遮蔽对白。

配乐开启且镜头时长已确定时，用现有镜号、时间窗和生成段边界标出少量关键声画锚点：配乐进入、显著换奏、对白让位、决定性接触和段尾接续。段内切镜须写音乐是延续、换奏、渐弱、骤停还是回归；没有音乐变化也说明延续，不能因切镜自行断层。未锁定时长时只写可见事件的先后，不编造秒点。默认声层优先级为可懂的台词/OS/OV、决定性动作音效、环境音、配乐；无对白或关键音效的段落可让旋律前景化。让位要写具体乐器或节奏如何减薄、何时恢复，而不只写“压低”。只有用户给出混音标定、明确 BPM 或节拍同步制作要求时才写相应数值；秒点是生成与后期对齐目标，不承诺成片逐帧精确。

未写收束或有因换曲时，下一镜须继承上一镜的主题/乐句位置、主奏、伴奏、节奏脉冲和演奏密度；镜头、生成段或生成单元边界本身不能触发断乐或重起。改变音区、奏法或声部须写剧情触发和保留的主题线索。跨生成单位分别写末镜音乐尾态与下一单位首镜入口；若分开生成，说明使用连续音轨或后期接续，不把独立生成的音乐宣称为已无缝。

## 导演工作顺序

1. 锁定剧情事实、能力规则、结果，以及战场边界、地标、实体障碍、敌我初始关系、武器和道具归属、能力源点。此时不锁死机位、景别、精细走位或路径。
2. 先按[知识库索引](references/screen-combat-craft-library.md)选当前力量系统的题材分册，提取会改变**打法、攻防限制、身体或结构受力、场景反馈**的少量机制，再确定本场独特的攻防问题、双方打法与能力/场地交点；有妖兽、法相、机甲或群战时，同时确定主体运动约束与战场目标。逐节拍分析新威胁、混合情绪、双方观察与反制、战术选择和控制权。为概述性空白补因果成立的攻防。若主能力是宏大奇观，在镜头设计前确定它怎样改变攻防、何时达到规模与亮度峰值、远近环境如何响应及后果怎样影响结局；再把动作、战术、人物、空间、视听和剧情线索推向既定结果。知识库只提供机制候选，不补写原剧情没有的能力、代价或结果。
3. 先定身体先兆、行动、接触或规避、反作用和余波，再联合设计观众需要看懂的事实与应感到的速度、重量或压迫。关键攻防与奇观段要判断摄影机是否应被冲锋、失衡、巨物增长或主效传播带动：可猛烈加速、改向、升降或抽离，也可在碰撞、尺度完整显露时骤停；静止应有蓄压或结果读取的作用。由此选起幅、观看距离、运镜、焦点、终幅；反向调整调度、动作路径、VFX 纵深、环境与声音。
4. 在内部预演中校正物理、接触状态、多人错峰反应、观看负载、特效主次和镜间连续。若不成立，先改调度、视角、遮挡、焦点、效果纵深或拆镜；不自动退回固定中景。选定方案后编译对应模式的 Markdown。

## 交付与校验

默认在对话中交付 Markdown；用户明确要求保存时才写文件。按指定目录保存，否则用当前工作区 `outputs/`；不覆盖源剧本或已有成稿，同名用递增版本。只交最终采用稿，不附内部候选、工程参数或审计表。

连续模式按[连续战斗合同](references/copy-ready-markdown.md)输出全局风格、视觉母版、Seedance 2.5 提示词、场景方案和镜头列表，默认每生成段不超过 30 秒。单生成单元按[单元合同](references/single-unit-delivery.md)输出，默认每单元不超过 35 秒。它们是本技能默认的生成单位上限，不应宣称适用于所有平台；用户指定不同目标时长或已核实的平台规格时按其要求设置上限并校验。若目标平台能力未核实，较长段落只能作为创作时长方案，不能保证可直接投喂。`SKILL_DIR` 必须是本技能目录的绝对路径；交付前可对临时 Markdown 校验：

配乐开启时，连续模式在全局提示词后附一条整场 `配乐总提示词`，只规定全局音乐、配音与声音优先级；每镜在原 `台词/音效` 字段内增加 `配乐` 子项，写本镜声画协同，不另设生成段配乐字段，八字段顺序不变。单生成单元在各镜对应的时间窗 `声音` 描述内增加配乐子项；`台词与声音层次` 可概述全单元配音原则，不另设单元配乐字段。关闭时不新增配乐子项或总提示词；已有稿件配乐按保留规则处理。字段细则与校验见对应合同。

```bash
python3 "$SKILL_DIR/scripts/validate_storyboard.py" <成品.md> --mode refined  # 连续
python3 "$SKILL_DIR/scripts/validate_storyboard.py" <成品.md> --mode single   # 单生成单元
```

覆盖默认时长时，连续模式追加 `--max-segment-seconds <秒数>`，单元模式追加 `--max-unit-seconds <秒数>`；有明确焦段要求时单元模式追加 `--require-focal-length`。

校验器只验证机器可判定的结构与时长。仍须检查剧情事实、动作因果、情绪、空间、特效层级和连续性；若成稿暴露具体质量缺陷，可重设受影响的节拍，并重新检查相邻镜头和校验格式。不因笼统的“更华丽”无限重写全场。
