# 创意优先的完整打斗制作协作流程

只在 `fight-scene-video` 已完成内部创意发散、导演融合和创意质量门后使用。任何专家模块都位于创意蓝图下游，不能提出替代概念或用默认模板覆盖原创动作、VFX母题、环境机关、反转和英雄镜头。

## 主状态包

所有模块都先接收：

```text
creative_hook: 这场打斗独特在哪里
creative_blueprint: 角色动作签名、VFX母题、场面力、层次与规模、宏大感证据链、环境机制、博弈、升级、摄影光影、英雄镜头
creative_kernel: 拆镜、生成适配和修复都不可牺牲的机制与画面
immutable_facts: 用户设定、剧情结果、能力边界、素材和禁止项
```

只有以上内容确认后，才追加执行字段：

```text
scene_state: 地标、材质、光源、合法路线、危险区
fight_beat: 当前创意事件、双方选择、控制权变化
action_vector: 起始姿态 -> 路径 -> 接触/规避 -> 受力/反作用 -> 落幅
ability_state: 来源、行为、交互、环境反馈、残留
spectacle_state: 力量占区、前中后景/高低层、尺度参照、环境级后果、余波
camera_intent: 本镜怎样呈现创意事件与权力变化
timing: 时长、动作触发、冲击点、切点
```

## 专家模块交接

### Frames Analysis

细化前中后景、高低空间、接触面、材质、VFX染色/遮挡、尺度参照和强弱构图。返回内容必须服务 `creative_hook`；不得把多层场面压成平面堆叠，也不得用常规人物居中构图替换英雄镜头。

### Camera Analysis

量化已定 `camera_intent` 的景别、角度、轨迹、速度、焦点、轴线和落幅。若原构想单镜不稳定，提出覆盖拆分，不能另选默认机位、删除创意事件或裁掉尺度参照。

### Overhead Trajectory Map

只接收批准后的平面、高度、道具、VFX占区和摄影机事实。返回调度参考，不改变创意蓝图；没有明显空间风险时不强制生成。

### Continuity Ledger

记录每镜真实落幅与 `creative_kernel` 的跨镜载体，包括动作势能、武器归属、伤势、VFX残留、环境破坏、曝光和控制权。下一镜从这些状态继续。

### Audio Design

在动作时点确定后设计预备、路径、接触、材质、静音和余波。声音强化原创动作与VFX行为，不用通用轰鸣掩盖视觉因果。

### Natural Emotion Performance

仅在表演直接改变佯攻、判断、忍痛或恢复时调用。每镜最多返回一个必要锚点，不新增情绪支线，不占用动作/VFX信息预算。

## 工程变更协议

任何模块建议改动时必须返回：

```text
保留的创意核：[原机制/画面]
发现的具体风险：[可验证问题]
最小改动：[拆镜/换覆盖/分阶段/降低同时性/稳定落幅]
创意保真检查：[钩子、母题、反转、英雄镜头是否仍成立]
```

禁止只返回“简化动作”“减少特效”或“改成稳定镜头”。无法保留创意核时把冲突交回 `fight-scene-video` 裁决，不得静默替换。

## 合并质量门

1. 最终镜头仍能复述原 `creative_hook`，并保留 `creative_kernel`。
2. 动作、VFX、环境、摄影和声音围绕同一个创意事件，并形成可读层次，不是并列装饰或平面堆叠。
3. 场面力、高潮尺度和宏大感证据链在拆镜后仍然成立。
4. 工程修改均有具体风险证据，且采用最小干预。
5. 位置、轴线、道具、伤势、残留、曝光和落幅连续。
6. 轨迹图、关键帧和提示词只是同一创意事实的不同表达。
7. 最终提示词不含专家元数据、地图标注或内部分析标签。
