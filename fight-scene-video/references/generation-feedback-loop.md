# AI打斗成片诊断与增量修复

用户提供已生成视频、关键帧、失败时间点或成片描述时读取本参考。目标是找到最早根因，用最小改动提高下一次生成稳定度，而不是重新堆一篇更长的提示词。

## 必要输入

- 已生成视频或按时间排序的关键帧；只有文字描述时标记判断置信度。
- 对应的原即梦动态提示词和负面提示词。
- 角色/场景参考图、本镜双视图轨迹图、动作锁、VFX卡和前后镜落幅。
- 用户认定必须保留的动作、风格、构图和结局。

缺少某项时仍可诊断可见问题，但不要臆测不可见的生成参数。

## 检查顺序

按时间从前到后找到最早错误帧。后续错误可能只是该错误的连锁结果。

| 优先级 | 维度 | 阻断级问题 | 常见根因 |
|---:|---|---|---|
| 1 | 身份/身体 | 换脸、服装突变、额外肢体、手指严重畸形 | 主体过多、遮挡、动作密度过高、特写同时做复杂动作 |
| 2 | 空间/连续性 | 左右互换、瞬移、穿墙、落点错误、轴线混乱 | 起终点不明确、摄像机与人物轨迹冲突、缺少稳定地标 |
| 3 | 动作因果 | 攻击无预备、武器穿身、接触不可读、受力方向错误 | 单镜动作链过长、双方同时高速、镜头遮住接触 |
| 4 | VFX | 技能脱离源点、穿人穿墙、遮脸、召唤物残缺 | 特效层级过多、路径未锁、主体动作与显化同镜过载 |
| 5 | 摄影机 | 漂移、无因果旋转、丢主体、突然换视角 | 多个主运镜、缺少绑定对象/制动点、视角名称未翻译 |
| 6 | 物理/质感 | 布料穿模、碎屑漂浮、光照不反应、材质错误 | 交互对象过多、VFX没有材质规则、残留状态未继承 |

前四项未通过时，不先调色、锐化、颗粒或分辨率词。

## 症状与根因

使用 `症状 -> 最早发生时间 -> 违反的锁 -> 根因 -> 最小改动` 格式。例如：

```text
症状：剑气在挥剑前已经出现并遮住右手。
最早发生时间：2.1秒。
违反的锁：VFX来源/触发、右手握剑连续性。
根因：提示词同时要求快速结印、旋身挥剑和巨大剑气爆发，触发阶段过载。
最小改动：拆除同镜结印；剑气只在剑锋完成满月轨迹后从剑尖延展。
```

不要把“模型不行”当作根因；必须指出可修改的动作密度、遮挡、空间、触发、镜头或提示词冲突。

## 修复优先级

1. 锁身份和身体：减少同框主体、减少手部复杂度、改用稳定中景或专用手部镜头。
2. 锁空间和落幅：恢复地标、起终点、屏幕左右、人物朝向和唯一镜头轨道。
3. 简化动作：保留一个承诺攻击、一个反应、一个结果；摔投和换手拆镜。
4. 修复VFX：放回唯一源点，减少层级和颜色，明确遮挡、落点、材质与残留。
5. 稳定摄影机：删掉次要环绕/甩镜/升降，增加制动和稳定落幅。
6. 最后调整质感：光照、曝光、运动模糊、粒子数量、材质细节。

若同镜存在两个阻断级根因，优先拆镜，不尝试用更长负面提示词强行解决。

## 增量修复模板

```text
必须保留：[角色身份、场景锚点、已经成功的动作/构图/VFX、前后镜连续状态]
必须删除：[导致过载或冲突的动作、运镜、特效层、额外对象]
本轮单一改动：[只写一个主根因对应的改动]
修复后动作链：[起幅 -> 预备 -> 决定性动作 -> 反应 -> 稳定落幅]
修复后VFX：[来源 -> 触发 -> 路径 -> 交互 -> 残留；无关则保持原样]
修复后摄影机：[绑定对象、一个主运镜、制动点、落幅；无关则保持原样]
新增负面约束：[3-6条直接针对本轮根因]
验收条件：[可在画面中客观判断的通过标准]
```

增量提示词必须明确“其余已成功内容保持不变”，但不要依赖模型理解抽象的“优化一下”。

## 单变量迭代

- 第一轮只修阻断级根因；通过后再修主要问题，最后处理美术细节。
- 一次只改变动作、VFX、摄影机、构图或光照中的一个主变量。
- 保留成功的随机结果：角色脸、服装、场景、光源、武器归属和已经正确的落幅。
- 记录每次提示词差异和结果，不把旧失败约束无限累加进负面提示词。
- 同一错误连续两轮未改善时改变表达结构或拆镜，不只是替换形容词。

## 验收标准

- 身份、身体、武器归属和场景锚点从起幅到落幅稳定。
- 攻击来源、承诺路径、接触/擦过、受力方向和结果可逐项指出。
- VFX从正确源点出现，遵守遮挡和材质反应，不遮主体信息。
- 摄影机完成唯一主运动并在结尾稳定，为下一镜提供可用状态。
- 修复没有破坏原本已成功的风格、叙事结果和连续性。

## 关键帧联系表工具

用户已提供按时间命名的PNG/JPEG/WebP关键帧时，使用 `scripts/build_review_sheet.py` 自动自然排序、编号并生成PNG联系表和JSON清单。先调用工作区依赖发现，使用其中带Pillow的Python：

```bash
<workspace-python> scripts/build_review_sheet.py --input-dir <frame-directory> --output <review-sheet.png> --title "<shot-id> review"
```

工具不负责视频解码。环境没有可靠解码器时，不声称自动抽帧；让用户提供关键帧、使用浏览器/平台截图，或安装受控视频解码依赖后再扩展。

## 复盘输出

输出：问题分级表、最早错误帧、主根因、必须保留、必须删除、本轮单一改动、增量即梦提示词、新负面提示词、验收条件。未提供成片时不要伪造逐帧结论。
