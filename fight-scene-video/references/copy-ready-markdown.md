# 一键复制 Markdown 导出

只在内部创意发散、导演融合、创意质量门和完整动作/VFX/摄影设计完成后读取。用户即使只要求 Markdown、一键复制或最终提示词，也不能从本发布层直接开始，更不能让参考排版反向决定动作、特效或镜头创意。

该文件只承载可直接复制或投喂的内容，不承载分析过程。用户示例只用于理解信息密度、阅读节奏和平台语法，不自动升级为必须逐字遵守的固定格式。

## 导出合同

- 写出 UTF-8 `.md` 文件。用户指定路径或文件名时服从；否则使用工作区的用户交付目录，文件名采用 `[场景名]_Seedance打斗提示词.md`。
- `.md` 正文不含外层代码围栏或无关解释。默认不混入轨迹图、合同、台账和风险分析；用户明确需要制作型 Markdown 时可以加入适量标题、目录或表格。
- 最终回复提供文件链接，并把文件正文逐字放进一个 `text` 代码块；代码块只用于聊天复制按钮，不写入文件。
- 文件与聊天代码块必须使用同一最终正文，不能一个是摘要、另一个是完整版。

## 自适应结构

- 优先沿用用户已经建立的层级、命名和阅读习惯；没有明确格式时再使用“全局视觉锁 -> 素材绑定 -> 逐镜正文 -> 负面提示词”的推荐结构。
- 格式随任务变化：少量镜头可用连续正文，多镜头可用镜号分段，需要直接粘贴平台时可减少标题，需要团队协作时可增加简短字段名。
- 不为对齐模板输出空字段，不强求每镜具有相同字段数。只要动作、VFX、运镜、光影、声音、台词和连续性事实能被准确读取，就允许合并或拆分字段。
- 用户说“参考这种格式”“差不多这样”时提炼其共同特征，不把标点、字段顺序、标题段数或中英文混排当成硬约束。

## 全局风格词

- 需要全局风格词时，推荐使用 `质量/模型风格 -> 时代与地点 -> 时间天气 -> 环境色板 -> 主体外观 -> 核心VFX色板 -> 光照与材质 -> 画面质感`；用户的平台或既有提示词顺序优先。
- 颜色写成 `语义 color:#RRGGBB`，同一对象只保留一个权威主色；不要在不同段落重复冲突色值。
- 用户已给全局词时保留其术语和资产意图，只清理重复 token、双空格和明显笔误；不得擅自改变角色、场景或风格。
- 生成新全局词时消除硬矛盾。例如出现具名角色或 `1girl` 时不能同时保留 `no people`；现代城市不能同时要求古代建筑，除非镜头明确需要两者并存。
- 全局词只锁跨镜不变的视觉事实；逐镜动作、运镜、台词和瞬时VFX变化不要塞入首行。任务不需要全局风格词时可以省略，不为满足模板强行生成。

## 素材绑定

用户提供平台素材标签时，严格保留标签和 ID，不加反引号：

```text
[角色名]：<node-asset>[ASSET_ID]</node-asset>。
[怪物/道具名]：参考<node-asset>[ASSET_ID]</node-asset>。
```

没有素材 ID 时省略对应行，不制造占位 ID。一个素材只绑定一个稳定名称，后续逐镜沿用该名称。

## 逐镜组织

高能镜头不得只写“主体动作 + 特效形容词”。在不制造空字段的前提下，正文必须让以下事实可见：前景受力证据、中景主体与主VFX路径、后景尺度参照、高低空间、至少一条环境连锁反应、光权变化和稳定落幅。高潮镜还必须出现两种不同材质或不同尺度的环境后果。纯触发特写、必要反应镜和转场镜可以豁免，但相邻宽镜必须补回空间与尺度。

用户要求减少人物微动作、表演或招式时，把信息预算转移给环境、VFX、空间和光影；不得因此压缩画面内容。若丰富画面超出单镜负载，增加相邻覆盖，不删除场面层次。

以下是推荐写法，不是固定协议：

```text
镜号 [两位编号]｜[景别/视角/构图变化]｜[一个主运镜及其画面结果]｜[秒数]s

画面内容：[主体、场景、起幅、主动作链、落幅；使用连续中文 prose]
动作与打击：[仅当本镜存在攻防、接触或技能碰撞时输出；写发力/蓄能、路径、接触/碰撞、受力/能量传播、反作用/位移、回收/硬直和环境结果]
特效：[来源、显化、路径、交互、透明度/材质、残留；无特效写“无”]
场面与层次：[需要宏大场面时写前中后景/高低空间、力量占区、尺度参照、环境级后果和余波；也可合并进画面内容或特效]
光影：[环境主光、VFX染色、投影/反射、体积遮挡、曝光变化与恢复]
音效：[动作拟音、低频冲击、材质声、环境声或声音桥；无则写“无”]
台词【[角色名]，[语气]】：[保持原文]
```

可把 `动作与打击` 合并进 `画面内容`，也可在动作密集镜头中独立成行；可把 `特效` 与 `光影` 合并，也可为复杂VFX拆开。没有台词时可写 `台词：无` 或省略台词字段，服从整份文件的阅读习惯。无论采用何种排版，镜头标题与正文中的运镜必须一致，单镜仍只允许一个主运镜，不要用表情或微动作填充缺失的动作设计。

`场面与层次` 不是固定必填字段，但宏大或高能镜头的正文必须让人看见力量占区、空间层级和尺度证据，不能只写“史诗感、震撼、宏大特效”。

发布前逐镜检查 `画面密度句`：`前景证据 -> 中景主体/路径 -> 后景尺度 -> 高低关系 -> 环境连锁 -> 光权变化 -> 落幅`。字段可以合并，但事实不能丢失。出现“环境震动、光芒大盛、特效炸裂、气浪扩散”等无法判断方向、材质、遮挡或结果的概括词时，改写为可见的传播次序和材料后果。

## 负面提示词

- 默认在文件末尾输出一组全局负面提示词；当不同镜头存在明显不同的生成风险或平台按镜生成时，允许在对应镜头下写专属负面提示词。
- 合并时按首次出现顺序去重；不要机械删除具有不同约束范围的近义项。
- 必须覆盖身份/肢体、武器归属、接触可读性、VFX来源与遮挡、光效污染、镜头漂移和场景风格漂移的实际风险。
- 禁止无差别重复粘贴完全相同的负面提示词；逐镜负面词必须针对该镜真实风险。

## 发布前检查

- 文档开头直接进入生成内容，不出现方法说明或格式解释；全局风格词可按任务需要保留或省略。
- 用户提供 `node-asset` 时标签必须成对闭合，ID与用户输入完全一致；未提供时不要求素材绑定段。
- 镜号、时长、主运镜、人物名称和前后镜状态连续。
- 每个战斗镜头都保留创意蓝图为其指定的动作/VFX事件，不因压缩排版退回通用攻防或泛用特效。
- 高潮镜保留主体动作、主VFX路径、环境受力和尺度参照；整段存在清楚的蓄压、释放与余波层次。
- 高能宽镜具备至少三层空间信息；高潮镜具备至少两种环境材质/尺度后果，并保留稳定英雄落幅。
- 每个VFX镜写清实际发生的环境主光、染色、遮挡/投影、反射、曝光变化和后镜恢复；不得用抽象光影词替代。
- 动作镜保留打击证据链，VFX镜保留光影与材质反馈；微表情没有挤占这些内容。
- 正向词无硬矛盾，负面提示词没有无意义重复，并与全局或逐镜使用范围匹配。
- 文件不含代码围栏；聊天只含一个承载完整正文的代码块。
