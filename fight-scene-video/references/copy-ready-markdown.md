# 一键复制 Markdown 导出

只在源剧本逐项锁定、剧本保真矩阵、受约束导演演绎和完整动作/VFX/摄影设计通过后读取。用户即使只要求 Markdown、一键复制或最终提示词，也不能从本发布层直接开始，更不能让参考排版或Seedance适配反向决定剧情动作。

该文件只承载已经通过拆镜、动作预算、并行时长校准和剧本资格审计的Seedance 2.5生成内容，不承载分析过程。本技能的逐镜发布格式是固定协议；除非用户在当前任务明确指定另一种格式，否则不得变更字段、顺序、分隔符或空行结构。导演蓝图、内部设计台账或未经收敛的完整设计不得作为最终主文件。

## 导出合同

- 写出 UTF-8 `.md` 文件。用户指定路径或文件名时服从；否则使用工作区的用户交付目录，文件名采用 `[场景名]_Seedance打斗提示词.md`。
- `.md` 正文不含外层代码围栏、标题、目录、表格、全局说明或无关解释，只由连续镜头块组成。轨迹图、合同、台账、风险分析和全局负面提示词需要时另建补充文件。
- 最终回复提供文件链接，并把文件正文逐字放进一个 `text` 代码块；代码块只用于聊天复制按钮，不写入文件。
- 文件与聊天代码块必须使用同一最终正文，不能一个是摘要、另一个是完整版。

## 固定结构

- 所有镜头使用同一六行信息结构：一行镜头标题，加五个必填字段。
- 镜头标题固定为 `镜号 NN｜景别｜一个主运镜及角度｜时长s`。镜号使用两位阿拉伯数字并连续递增；分隔符使用全角 `｜`；时长使用阿拉伯数字紧接小写 `s`，如 `2.2s`。
- 固定字段依次为 `画面内容、特效、光影、音效、台词`。每个字段独占一个自然段，相邻自然段之间保留一个空行。
- 字段无内容时必须写 `无`，不得删除字段，也不得新增或改名字段。
- 不使用Markdown标题符号、粗体、列表、表格、P编号或括号标签装饰镜头标题。

## 全局事实处理

跨镜角色、场景、色板和核心VFX规则仍需内部锁定，但最终正文不得增加“全局视觉锁”栏目。每个镜头是独立生成单元，必须把当镜可见且生成所需的人物位置/朝向/肢体、对手位置/威胁动作、活跃VFX、环境破坏与光照状态自然写入 `画面内容、特效、光影`；只避免机械重复与当前动作无关的信息，不能依赖模型自动记住前镜。

## 素材绑定

用户提供平台素材标签时，在人物、怪物或道具首次出现在本镜的 `画面内容` 中紧随稳定名称写入对应 `<node-asset>` 标签；不得为素材绑定另加栏目。没有素材 ID 时不制造占位 ID。

## 逐镜组织

每镜先绑定内部 `原文证据 + P事件`。所有新增内容分为 `N必要补足` 或 `E演绎增强`；E只允许强化原动作的预备、力量路径、接触/规避证据、环境后果、粒子、光权、声音和摄影。删除全部E后，人物决策、动作顺序、战力、空间结果、台词与结局必须和源剧本完全一致。最终生成提示词不设固定字数上限；只精简重复形容、同义复述和无执行价值句子，不得压缩画面状态、动作因果、VFX演化、光影结果或稳定落幅。

高能镜头不得只写“主体动作 + 特效形容词”，但丰富度必须按剧情峰值分级分配。内部先按 `L0静场、L1源点、L2威胁、L3蓄压、L4唯一高潮、L5余波` 标记，最终生成文本不显示标签。正文让本镜必要的主体、主VFX路径、光权变化和稳定落幅可见；L1/L2不为凑层次提前用尽最大亮度、全巷占区、完整环境连锁和最高粒子密度，L3建立压迫与曝光欠债，L4才聚合三维尺度跃迁、代表性作用、群体结果和光权峰值。高潮镜优先使用两种不同材质或尺度的后果证明规模，但不得为凑数量新增源剧本没有的破坏。画面丰富度优先采用 `一个主奇观 + 一个核心粒子系统 + 一至两条因果证据`；粒子写清来源、密度/粒径梯度、速度、视差、流向和停点，不用多个无关粒子名堆砌。

突出人物主体时，只重排读取顺序，不删减本镜VFX事实。推荐顺序为 `人物第一读点 -> VFX源点/前态 -> 结构展开与传播路径 -> 威胁或碰撞 -> 环境/粒子/光影后果 -> 人物与VFX共同落幅`。人物可保持最高锐度和局部亮度，VFX则用更大的纵深占区、环境染色、投影和受力粒子证明规模；不得把主VFX缩成贴身泛光或把逐镜描述移到全局段后省略。

修改既有稿件时逐镜做 `VFX保真差分`：`主机制 | 屏幕/空间占区 | 环境链 | 粒子来源/方向/停点 | 光权变化 | 残留 | 奇观等级 | 峰值资源去向`。新版允许改变相对亮度、锐度、遮挡和构图位置，也允许把非源文E演绎资源从普通镜移给L4高潮；必须保留源剧本事实和必要功能，并让整组尺度、空间、光影曲线更清楚。过载时增加相邻覆盖并保持剧本信息总量。

用户要求减少人物微动作、表演或招式时，把信息预算转移给环境、VFX、空间和光影；不得因此压缩画面内容。若丰富画面超出单镜负载，增加相邻覆盖，不删除场面层次。

以下是唯一默认写法：

```text
镜号 01｜超远全景｜镜头缓慢向前匀速推进，微俯角｜2.2s

画面内容：深夜都市背街，狭长安静的城市小巷向黑暗深处延伸，街道空无行人车辆。深灰沥青路面，两侧围墙，后方是成片高层居民楼黑色剪影，零星路灯散出微弱昏黄光晕，远处城市天际线飘着淡淡的城市光雾。巷心孤零零伫立宋棠一人。

特效：空气漂浮细微都市扬尘颗粒。

光影：冷调月夜，高位冷白月光，环境大面积压暗，路灯微弱暖黄点状光源，明暗反差强烈。

音效：城市远处微弱车流底噪，巷内死寂。

台词：无
```

`画面内容`按 `必要独立起始状态 -> 人物第一读点 -> 执行者/肢体或能力 -> 起点/路径/对象 -> 接触或规避 -> 反作用 -> 稳定落幅` 组织。`特效`按 `可见源点 -> 动作触发 -> 主体结构 -> 传播/第一作用 -> 核心粒子与环境受力 -> 停止或残留` 组织。`光影` 单独写环境主光、VFX染色、投影/反射、体积遮挡、曝光变化与恢复。不得因固定五字段而删减这些事实。

最终正文禁用 `继承镜XX、镜XX状态、前镜、上一镜、下一镜、同上、沿用、继续上一镜、保持此前状态` 等跨镜替代语。可以写“仍悬在宋棠脚下的黑雾向两墙回卷”这类当镜可见事实，但不能只写“黑雾继承上一镜”。

`音效` 写环境声、动作拟音、冲击、材质声和声音桥。`台词` 保留原文；多人对白、OS、OV或系统音在同一字段内以 `角色/类别：“内容”` 顺序串联。没有内容一律写 `无`。对白与动作按时间轴并行计算，不机械相加：完全并行取最大值，部分并行只累加不可重叠时间；同时检查口型、呼吸与身体动作是否兼容。对白只统计实际正文并计入标点和表演停顿；说不完时拆镜或延时，不能压缩原文或新增对白字段。

发布前逐镜检查与等级匹配的 `画面密度句`：源点镜检查主体、源点和落幅；威胁/蓄压镜检查占区、压迫轴和曝光欠债；高潮镜检查 `前景证据 -> 中景主体/路径 -> 后景尺度跃迁 -> 低中高关系 -> 环境连锁 -> 光权峰值 -> 落幅`；余波镜检查回收和环境光恢复。出现“环境震动、光芒大盛、特效炸裂、气浪扩散”等无法判断方向、材质、遮挡或结果的概括词时，改写为可见的传播次序和材料后果。

## 负面提示词

负面提示词继续作为内部生成风险检查。用户明确需要时另建补充文件，不得插入固定逐镜正文，也不得在镜头块中新增“负面提示词”字段。

## 发布前检查

- 文档第一行必须直接以 `镜号 01｜` 开始，全文只含固定镜头块，不出现方法说明、全局风格词、素材绑定段、标题、表格或负面提示词。
- 每个镜头必须严格匹配 `标题 -> 空行 -> 画面内容 -> 空行 -> 特效 -> 空行 -> 光影 -> 空行 -> 音效 -> 空行 -> 台词`；五个字段一个不少、一个不多。
- 用户提供 `node-asset` 时标签必须成对闭合，ID与用户输入完全一致，并嵌入首次需要它的 `画面内容`；未提供时不制造素材标签。
- 镜号、时长、主运镜、人物名称和前后镜状态连续；同时每镜独立重述当前动作生成所需的起始状态，不出现跨镜替代语。
- 每个核心动作能唯一回答执行者、肢体/能力、起点、路径、对象、接触/规避和稳定结果；手型或持物变化有可见转换。
- 画面、特效、运镜、光影和音效没有使用相反修饰词软化或扩大原文的速度、突然性、同步性、次数、声音与环境力度。
- 剧本保真矩阵覆盖率100%，每镜能指回原文证据；删除额外演绎后，剧情、战力、顺序、空间结果和人物决策完全不变。
- 没有为增强张力擅自新增攻击、躲避、反制、能力、伤势、台词、受限、规则变化或反转。
- 运镜具备绑定对象、动作触发、单一轨道、信息揭示和结果制动；高速躲避不被无关环绕、甩镜或连续变焦干扰。
- 每个战斗镜头都保留剧本锚定演绎蓝图中仍位于执行预算内的动作/VFX事件，不因压缩排版退回通用攻防或泛用特效。
- 高潮镜保留主体动作、主VFX路径、环境受力和尺度参照；整段存在清楚的蓄压、释放与余波层次。
- 高能宽镜具备至少三层空间信息；高潮镜具备至少两种环境材质/尺度后果，并保留稳定英雄落幅。
- 每个VFX镜写清实际发生的环境主光、染色、遮挡/投影、反射、曝光变化和后镜恢复；不得用抽象光影词替代。
- 动作镜保留打击证据链，VFX镜保留光影与材质反馈；微表情没有挤占这些内容。
- 人物主体或一致性修订没有造成VFX机制、规模占区、环境链、粒子链、光权和残留缩水；全局VFX说明没有替代逐镜局部演化。
- 正向描述无硬矛盾；内部负面提示词不进入正文。
- 文件不含代码围栏；聊天只含一个承载完整正文的代码块。
- 每镜符合Seedance 2.5执行合同：单一核心动作、单一主运镜、按时间顺序、自足状态、无互斥姿态、可见结果明确；动作、对白、VFX与运镜按时间轴并行关键路径计算；过载时拆镜而不改剧本。
- 交付前运行 `python scripts/validate_storyboard_format.py <成品.md>`，并确认镜号连续、字段顺序固定、空字段写“无”、正文无跨镜替代语、短镜头无明显文字或顺序标记过载。最后人工执行反向复述；静态校验不能替代动作语义审片。
